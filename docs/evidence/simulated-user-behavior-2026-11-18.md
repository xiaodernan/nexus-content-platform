## 诚实解读（为什么 p95 比上次差这么多）

1. **本机最近重启**（期间所有 28 个 docker 容器整体冷启动，可用内存一度只剩 ~0.5 GB），Next dev 以冷 Turbopack 为主；p50/p95 高出上次一两个数量级——这是**设备受限下的观测**，不是回归。§159：不把慢归咎于代码之外的东西，也不装作没差。
2. **100% 零 5xx / 零超时 / 零连接拒绝**——在 rage-clicker 连击（28 hits / 8 会话）下也没有一次崩溃；服务可用性证据成立。
3. `lost-wanderer` 与 `bot-ish` 的尾部时延拉满（p95≈10-13s）主要对应冷编译单次命中（首载 10+s 后缓存命中即快）；"公有路由在合成流量下没有穿透"这条仍然成立。
4. 使用边界不变：这不是生产 SLA；真实撞库端到端（HTTP 风暴 ≥ 数百并发）本机 RAM 压不了，仍如实挂账（见 CURRENT-STATE cont.327 诚实边界）。
