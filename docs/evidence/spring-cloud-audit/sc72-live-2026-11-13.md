## 这回答了什么

- **5 个 NEXUS JVM 在本机能冷起**，`/actuator/health` 全 `200 {"status":"UP"}`——health 是「服务自己查」来的（domain-service 对 PG 55433 `SELECT 1` 的 Hikari 结果、nexus-config/api 验各自默认值），
  **不是静态 stub**；
- `show-details: never` 的 `/actuator/health` 契约被真实响应印证（无 stack、无 JDBC URL、无主机名）；
- `/actuator/info` 的 `build.component` 逐个被 pin 证（maven build-info 真的、不是手写 properties）；
- `domain-service` 的 circuit breaker timer 可见且 `ai-service=CLOSED`（本窗口没真打 ai provider 的路，但 break-list 能读）。

## 没回答什么（如实）

- 没联通 `nexus-registry`↔config↔api/domain 的 **真服务发现**循环（每个 JVM 都是独立起落；不意味着三者真互相发现/负载均衡）；
- 没测 `nexus-gateway` 到 upstream 的 **真代理** 路径（取决于 trusted `NEXUS_REGISTRY_PORT` 上下游 8771 环境，本机只守住 registry/api/gateway 各自的 health；没有真代理流量打上来）；
- 没跑 `/admin/health` 五层快照（§SC-NEW / FE-40 的 `/admin/health`-page 沉淀的是 `.admin-health aggregate`，但 `nexus-gateway` 仍是「只被 health 探过，真代理路径没打」）；
- `REDIS_HOST:VAL` 与 `REDIS_WAITFOR` 仅凭环境（nexus-redis 跑 56379 是 healthy container；但 gateway 默认 REDIS-backend `memory`，没切到 shared ——这正是 `docs/ENVIRONMENT.md` 明确说的"默认 backend=memory"）。
- gateway 默认限流 `memory` 模式（每实例单独计数），**没切到 Redis 跨实例共享**（`NEXUS_GATEWAY_RATE_LIMIT_BACKEND=redis` 在 ENVIRONMENT.md 留待操作）；不是在代码里不能跑，是一次 env flip。
