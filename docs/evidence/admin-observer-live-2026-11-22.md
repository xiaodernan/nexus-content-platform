# 只读观察站 · 口令 123 门 + 真实指标真机核对（2026-11-22 · §ADMIN-13 续）

> 用户要求「开发管理员功能（密码输入 123 就能进，所有用户都知道密码也都能进管理员页面），
> 用来检测、分析、查看、观察所有用户的行为。管理员页面能监控所有用户的统计数据、
> 做分析和趋势预测，并根据这些数据给出下一步应该采取的深度优化措施」。
> 本篇是这套功能在真浏览器里的端到端读数。

## 口令门（公开口令，不是鉴权秘密）

- 游客打开 `/admin/observe` → 只看到守门表单，表单上**明写**「口令公开：123」，
  并说明「它不是鉴权秘密——它是一扇只读的窗：你能看见每一个数字，你什么也改不了」；
- `POST /api/admin/observer` 输 `123` → `200 {"ok":true}`，响应里
  `Set-Cookie: nx_observer=observer-123; Path=/; HttpOnly; SameSite=lax; Max-Age=2592000`；
- 带该 cookie 再打开页面 → 守门表单消失（`data-observer-gate-form` 不在 DOM），
  观察站本体渲染；
- 同一 IP 每小时 30 次尝试的防刷闸在路由里（进程内计数，跨实例不合并——这一点写在注释里）。

## 过程中记录的环境事实（不是产品缺陷）

本轮两次量到 `/admin/observe` 500，根因都是 **Docker Desktop 的 Linux 引擎掉线**：
`nexus-platform-postgres`（5433）随之不可达，`readObserverMetrics` 的第一条查询
（`select count(*)::int as n from users where deleted_at is null and guest = false`）
拿到 `CONNECT_TIMEOUT`。引擎恢复后同一条查询立刻返回 32。
页面本身有 `app-root-error` 兜底（"这不是你的操作问题——页面背后的那段代码抛了一个异常"），
没有把异常裸摔给用户。
