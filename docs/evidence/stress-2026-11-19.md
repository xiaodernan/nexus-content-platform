## B · §STRESS-3 网关撞库令牌桶 · Lua 在真 Redis 上的直连验证（2026-11-19）

`npm run ratelimit:gateway-lua`（scripts/gateway-rate-lua-live.mts）——
不经过任何 JVM，只把 `services/nexus-gateway/.../RedisRateLimitBackend.java`
**源码里那段 `String LUA = """ ... """` 本身**读出来跑在 redis://127.0.0.1:56379：

- `SHARED_BUCKET_CAPPED: PASS` — 同一只键（EVAL 次数=1/1/0 …），第三次被拒是**共享计数**给的
- `PER_INSTANCE_CONTROL: PASS` — 对照组：相同脚本、同 burst=2/rate=0，换成另一只键 → 1/1/1 放行
- `ATOMIC_BURST_THREE_CONNECTIONS: PASS` — 3 条独立连接同时各打 4 次，burst=3 → 合计恰放行 3 枚
  （并发 12 次里放行 2 枚），桶里剩 0；不原子的读改写会让这里 >3
- `REFILL_FROM_SERVER_CLOCK: PASS` — 打空→等 1.1s（rate=2/s→补 2.2，夹到 capacity=2）→ 再问放行 1
- `FUTURE_STAMP_REFUSES: PASS` — ts 写到未来 30s（另一台时钟快的形状）→ 这一问 = 0，elapsed 夹 0
- `TTL_IS_THE_ARGUMENT_AND_IT_EXPIRES: PASS` — ttl 由调用方传入生效（1191ms），到 1.4s EXISTS=0；
  rate=0 的桶 PTTL ≈ 一小时 → 调用方决定的桶不会永久驻留

判词：网关的共享限流 Lua（撞库/洪峰场景的最后一道闸）在真 Redis 上自洽
（6/6），脚本 sha256:8db0f4043dd7。读数落在 `.scratch/gateway-rate-lua-live/readings.json`。
