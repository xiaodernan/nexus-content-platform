## 诚实结论

1. **500 个请求全部 2xx，0 个网关 5xx、0 个断。**（1630 次/16200ms 级冷编译全家桶都在内）
2. dev 冷编译 p50 约 8–13 秒——这条线跟上次一样走 Turbopack 冷路径；**不代表生产 P50**。
3. 压力点没在 p50，而是在 **编译-then-serve 的内存驿旧屏障**——下一轮如果做「热缓存分层」实验才有意义：重启后首发路径已经 warm，后续 p50 掉回亚秒区间（这次没做第二遍 warm 探测，属于限制留给下一次）。
4. **并行 100 请求 × 2 档全都做到了（tier-48）**，没有 OOM、没有 5xx；本机仍在 4GB 空闲线上，超过这个档位的并发不建议再上（内存安全线）。
5. 复测必须在**单 dev server**下跑（Next 16 不允许同一项目并行 dev）；2026-11-17 的 3401 证据保持原样，不倒灌到本次。
