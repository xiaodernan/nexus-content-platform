# 问典引用机检：从硬编码错号黑名单改成查表（2026-11-22 · §CANON-VERIFY）

> 起因是上一轮的一个实测：问「那道浅痕最后变成了什么？」，模型答
> **"浅痕后来变成了半枚潮印。依据回响二十一章《值更院抄本院那本册子翻过第七十二页之后》的锚句。"**
> 内容对，出处是编的。当时以为是"引用了不存在的章回"——查进去发现两件更严重的事。

## 旧实现的形状

`verifyCanonDraft` 里的「发明章回」是一张**硬编码的正则黑名单**：

```
/第六章|第七章|第四十二|第四十三|chapter (6|7|42|43)|echo 0?(37|38)|E ?-? ?3[789]|第三十七回响/i
```

git 历史确认：写它的时候（2026-11-17，`f1df3ab5`）正典只有 **5 章 / 36 回响**，
所以第六章、第七章、Echo 37/38/39 当时**确实是**发明的。这张表在当时是对的。

之后正典长到 **13 章 / 210 回响**，表没有跟着更新。于是它同时坏在两个方向：

**误报（把真引用判成发明）**——`第六章`、`第七章`、`Echo 37`、`E37` 全是真引用，
旧机检会给答对的模型打上 `invented-chapter-or-echo`，逼它走一轮无意义的 revise。
`canon-answer-graph.test.ts` 里三条用例**把这个错误行为当成规格钉住了**
（`expect(...).toContain('invented-chapter-or-echo')`）。

**漏检（只抓那三个号）**——`回响二十一章`、`第三百回`、`Echo 999`、`Chapter 99`、
`第两千零一章` 全部静默放行。

## 改法

全部从 digest **现取**，不硬编码：

1. `digestSectionNumbers(digest)` —— 从 `## Chapter NNN ·` / `### Echo NN ·` 头部
   取真实章号/回响号集合（当前 1–13 / 1–210）。
2. `extractSectionCitations(text)` —— 七种引用写法：`第 N 章`、`第 N 回响/回/篇`、
   `回响第 N 章`、`回响（其 N）`、`回响 N`（阿拉伯）、`Chapter N`、`Echo N`、`E N`。
   **后缀写死**：`第 N 次`（第四十一次大会是真事件）、`一百三十一题` 绝不误报。
3. `digestQuotedPhrases(digest)` + `extractQuotedTitles(text)` —— 书名号短语查表。
   集合同时收「正文里的《…》」和「所有节标题（中英）」：只收前者会把正确的
   《里巷子码头的七盏号灯》判成发明（标题在 digest 里不带书名号），只收后者会漏掉
   《收件人》《潮沙盘》这类正文书名号概念名。
4. `parseChineseNumber` —— 中文数字解析。**逐位写法优先**：`二〇八`=208、`二一〇`=210。
   按位值相加会把 208 读成 8、210 读成 0——后者会把正确引用误报成"发明了第 0 回"。

三问都过了机检，其中第二问正是**逐位写法**（二〇八、二〇九）——它曾在旧解析器下会被读成 8 和 9。

## 仍欠

- 书名号检查要求**逐字一致**：模型把标题换个近义说法（"那本自己翻页的册子"）仍会放行。
  要治这个得做模糊标题匹配，而模糊匹配的误报率还没量过——宁漏不错。
- `E N` 缩写模式可能与英文句子里的 "E 5"（编号列表）撞上，尚未实测。
