## 这个工具做了什么 / 没做什么

**做了**：把 1,284 行正典（索引 + 626 条锚句）压成一次 24K token 的调用，
输出结构化 A/B/C/D 四条，每条带理由；模型自己说清"索引里没有的信息我不下结论"。

**没做**（如实）：它不认识正典全文，所以"纪元是否与 E206–E210 一致"这类问题它明确说无法核实；
锚句是否在**正文里逐字出现**它也无法核验（那本来就是 `verify:world-bible-anchors` 的字节级差事）。
评审意见是**意见**，采纳与否在人——脚本头部与输出都这么写。

## 网络路径备忘（本次实测）

同一把 key：带 `Bearer ` 前缀 → **401 无效的令牌**；裸 key → **200**。
不带代理 → **403 本站不对您所在的国家及地区进行商业服务**；走 7897 → 200。
两条都不是 key 的问题，是**认证头格式**与**出口路径**的问题，脚本里都写明了。
