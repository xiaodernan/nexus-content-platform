九个评测维度里，这里只测**本机不靠模型就能测**的，并且每一项都跑生产真路径：
RAG 走真库索引与真检索，设计精度走真 provider（当前是 DEMO 规则 provider）与真

不断言任何阈值——数字记在这里，回归靠人眼比对（同 `docs/PERFORMANCE.md` 的纪律）。
但**结构不变式**失败时脚本以非零码退出，因为那是回归而不是"数字难看"：

- RAG 负对照必须返回空（不存在的锚句不许被"检索"出来）

- 补丁引用完整性（捏造 id = 幻觉）必须为 0
- 补丁应用必须零 skip；响应必须过 zod 契约
- codegen→parse 往返必须零补丁零 issues

- a11y 干净基线必须满分，注入的 4 类违规必须 4/4 检出且定位到节点

### 只用键盘的人能不能走完这一页（键盘可达性 · e2e/keyboard-a11y.spec.ts）

axe 量的是 DOM 的形状（有没有名字、对比度够不够），量不到 tab 顺序、焦点可见性，
也量不到"点了会翻页的东西能不能被 Enter 按响"。载体用 §167 那份两页互动稿
（首页一个 `click → navigate` 节点）：它是平台上唯一"必须按一下才走得通"的公开页，
所以也是唯一能被键盘走查证伪的地方。访客匿名、只用键盘，`navigator.webdriver` 照 §167 盖掉。

2026-10-28 读数：**分母（DOM 里可聚焦的控件）9 个 · 走查 11 步 · 页内命中 9 个（覆盖 9/9）·
排除项 1 个（评论「发送」按钮 disabled，空输入时本来就不该可达）**。tab 顺序逐字等于 DOM 顺序：
举报 → 点赞 → 关注 → Remix → 收藏 → 作者主页 → 复制链接 → 评论框 → 热点。
焦点指示：前 8 个走 UA 默认环（computed `outline: solid 2px rgb(91,108,255)`），
热点走 Tailwind ring（`box-shadow`，它自己写了 `focus:outline-none`）——页内**无指示的停留点 0 个**，
唯一没有指示的是 Next 的开发工具 portal（在 `[data-published-root]` 之外，不是我们的界面）。
焦点按 Enter 落在热点上：URL 变成 `?page=<终点页>`，`/api/published/work-complete` 回 **200 且
`recorded: true`**——键盘走通与鼠标走通进的是同一个数，不是另开一条假路。

六道结构不变式（首个红会遮住后面的门，所以"点名到缺陷"的那道放在最前）：
非空转 / 热点在册 / 无陷阱 / 覆盖 / 顺序 / 焦点可见。变异臂 4 条（0=基线不改，跑完逐字节 md5 复核还原）：

| 臂 | 缺陷 | 预测的首个红 | 实测 |
| --- | --- | --- | --- |
| 0 | 不改 | 全绿 | ✅ 1 passed |
| A | 「复制链接」加正 `tabIndex={1}` | 门「顺序」 | ✅ MATCHED |
| B | 热点加 `tabIndex={-1}` | 门「热点在册」 | ❌ 第一版红在门「顺序」 |
| C | 热点摘掉 `focus-visible:ring-2` | 门「焦点可见」 | ✅ MATCHED |

**B 这一臂否证了我写下的两句判据**，两句都已照实测改写：
① 我原以为门「覆盖」能抓到"控件被改成 `tabindex=-1`／`disabled`"——抓不到：这两种写法会让控件
**从分母里一起蒸发**，两侧同源就永远相等。现在排除项照实打印成读数，热点由「热点在册」那道专门门盯。
② 我原以为 B 会先在热点那道上红——实际浏览器在热点退出 tab 序后，给投影出的根节点框**补了一个
tab 停留点**（读数里那个 `div#NEXUS STUDIO…`），顺序门先红。红是真红，但报的不是这个缺陷，
所以把「热点在册」提到走查之前重跑，B 才按名字红（上表记的是重跑后的结果）。
浏览器为什么会补出那个停留点，我没有证据，不作解释。

顺带量到一条评测自己的运行条件：注册按 IP 限流 **10 次/小时**，而 e2e 有 10 个文件各注册一个新账号——
连跑第二轮就会 429，界面上只留 `data-auth-identity="guest"`，看着像用例坏了。今天两次红都是这个原因。
**没有为测试放宽那道闸**：报错里改成直接印 HTTP 答复码与限流说明，节奏限制写进 `docs/ENVIRONMENT.md`。

**而那句"报错里印答复码"的诊断自己把绿的路径卡死了**（同日下一轮实测，上表那四条臂是在诊断加进去
之前跑的）：诊断要读界面上的 `[data-auth-error]`，用的是 `locator.textContent().catch(() => null)`——
注册**成功**时那个元素根本不存在，Playwright 于是先等它出现，而 `actionTimeout` 没设（= 不限时），
`.catch()` 只在测试超时把等待 reject 掉的那一刻才生效。实测一次 `count()` 用 117ms 报"元素不在"，
紧接着同一元素的 `textContent()` 挂了 **145 秒**，直到测试超时才吐出 null——**基线从"能过"变成
"必然整条测试超时"**，而报错写的还是那句"注册没把会话升成 member"，把人的注意力往限流上带。
改成一次性读数（`page.evaluate(() => document.querySelector(...)?.textContent)`，元素不在就是 null），
同一条腿 9.6 秒绿，上面那组读数（分母 9 / 走查 11 / 命中 9 / 排除 1）一字不差地复现。
教训一句：**"等一个不该存在的元素"不是稳妥的兜底，是把绿路变成死路**——读"有没有"要用不等待的 API。

### 登录后那九张界面长什么样（axe × 真浏览器 · e2e/a11y-internal.spec.ts）

第二片只扫了公开作品页，而平台上被看得最多的不是那张：Studio 是创作者一整天待着的地方，
发现／市场／通知／数据／搜索／额度／凭据是别人进来的门。**axe 扫不到的面就不许说它"过"**，
所以第四片把面扩出去。一次注册扫九张（注册限流见上一节），每张先等它真的渲染出来的判据，
再跑同一套 WCAG 2.0/2.1 A+AA；排除项仍然只有一处、并且写在报错与这里：Next 的开发工具 portal。

三类缺陷，两条根因：

1. **强调面上的文字（`color-contrast`）不是手滑，是 token 层的系统错**。首页那条红的是
   `button.bg-accent-2.text-fg-1`（保存简介）：暗色下 `#eef1f6` 压 `#22d3ee` 只有 **1.60:1**。
   拿同一把尺子量全库的"同一条 class 串里底色+文字"配对：67 条里 **36 条不及格**，跨 25 个文件——
   其中 32 条就是 `bg-accent-2 text-fg-1` 这一种写法。根因是**两个 token 各自都对、拼起来必错**：
   三个 accent 是亮色且**不随主题翻转**，`fg-*`／`bg-*` 却跟着主题翻（暗近白、浅近黑），
   所以"亮色实底 + 任一文本 token"必然在某个主题上塌。修法不是逐处挑颜色，而是给这类底色一个
   不翻转的前景 token `--nexus-color-accent-fg`（`#0a0b10`，对七个强调面 4.64～10.88），
   并把 46 条串换过去（32 个文件）。顺带清掉一个坑：`--nexus-color-brand-fg` 声明成 `#ffffff`
   却**从没被引用过**，而白字压 brand 只有 4.17——它看着像"品牌面的专用前景"其实是不及格的诱饵，删。
2. **控件没有可及名（`label`／`select-name`）**：读屏用户听到的是"组合框"三个字，而界面上一行有六个。
   首跑抓到 5 处（两个文件框 + 三个 `select`），全部补上 `aria-label`。

**然后这道浏览器门自己露了底**：axe 只看得见**渲染出来的** DOM。把同一判据拿去找全库，又翻出
6 处一模一样的缺名字，它们全在**默认收起的面板**（设计系统、属性、变体板）和**点开才出现的表单**
（公开页的举报理由、后台的档位选择）里——浏览器那道门结构上不可能看见它们。所以补了两道确定性门：

| 门 | 钉什么 | 首跑（HEAD 改之前） | 现在 |
| --- | --- | --- | --- |
| `style-tokens.test.ts`「强调面上的文字」 | 同串 `bg-*` + `text-*` 按 tokens.css 字面值算，两个主题每条 ≥4.5；`accent-fg` 在两个主题下对每个强调面都 ≥4.5 | 36 处不及格（暗色）；浅色那 22 处当时看不见，见第五片 | 0（该文件 12 条用例全绿） |
| `control-names.test.ts` | 每个 `<select>`／`input[type=file]` 自带名字（`aria-label`／`aria-labelledby`／`title`／被 `<label>` 包住／`id`+`htmlFor`） | 11 处裸控件 | 0（3 条用例全绿） |

两道门都带"验电"：改之前的写法（`fg-1` 压 `accent-2`、白字压 brand）必须不及格，
判据本身要能红（裸标签抓、三种合法写法放、`onChange={(e) => …}` 里的 `>` 不许把开标签截断）。
`control-names` 那条还顺手推翻了自己第一版的一个假绿：**注释里写"某个 token 为什么被删"会被
`--x:` 的正则当成真声明**——token 名现在只从去掉注释后的文本里读，并用一对断言钉住这件事。

改完复跑九张：**违规 0 条 / critical 0 类**（通过数 25/23/19/22/21/20/21/19/22，17.6 秒）。
带水合屏障的键盘走查同轮 10.4 秒绿。

**这一片也推翻了一条我自己写下的归因**：上一节说"今天两次红都是限流"。今天同一类"身份仍是 guest"
又出现一次，而答复码是 **0——POST 根本没发出去**。真正的成因是这些界面 SSR 出来的：HTML 一 attach
就能 `fill`／`click`，可那一刻 React 的委托监听还没挂上，点下去**静默丢掉**；同一脚本两次跑一次成一次败。
`waitForSelector('[data-auth-tab=…]')` 只等得到 SSR 的 HTML，等不到水合，所以它不是屏障。
判据只能换成"点下去之后 DOM 真的按状态变了"（切一次登录／注册，看只有注册态才渲染的昵称框消失再回来；
建项目则看 `disabled={busy || !name.trim()}` 那颗按钮被点亮），落进 `e2e/support/auth-session.ts`。
**分辨办法就是看答复码：0 = 点击被吞，429 = 限流**——上一节那句"都是这个原因"因此只算说对了一半。
另有 9 个 e2e 文件仍是老的无屏障写法（`data-auth-email` 一填就点，今天全绿的记录不变），
已按名字记进 `docs/ROADMAP.md` 的技术账。

#### 第五片：还浅色那笔账时，发现门自己在无声跳过（2026-10-28 同日）

第四片记了一笔"今天不算违规、只因为产品里没有切到浅色的入口"的账（`bg-brand text-bg-0` 浅色 4.17）。
还账的动作很小：把"同串底色+文字"那道门从只查暗色扩到两个主题。**扩完它没有红，而是继续绿**——
这就是比那笔账更严重的发现：

| 症状 | 量出来的事实 |
| --- | --- |
| 门绿着，但看不见 `text-bg-*` 这类前景 | `valueOf()` 连用两次 `replace` 剥前缀，`text-bg-0` → `"0"` → 查不到值 → 走"不是本文件的色"那条 `continue`。**跳过不报错、不计数** |
| 修好解析器后红出的真账 | **22 处**：`bg-brand text-bg-0` 12 处（浅色 3.93）、`bg-warn text-bg-0` 7 处（**1.91**）、`bg-success text-bg-0` 3 处（2.15） |
| 修法 | 换成不翻转的 `text-accent-fg`（12 个文件／22 条串）。暗色下 `bg-0` 本就是 `#0a0b10`、与 accent-fg 同值，**看得见的主题零变化**，只是把跑不到的主题从"迟早塌"变成"已过 AA" |
| 反向量同一把尺子（强调色**当文字**） | 又 194 处：`text-accent-2` 85／`text-danger` 73／`text-warn` 36。暗色最低 4.64 全过，浅色 **1.46／1.64／2.72** 全塌。同一根因：强调色不翻，表面翻 |

教训不是"浅色主题要修"，而是**门禁里那条 `continue` 是危险语句**：一条"读不懂就放行"的分支，
会让一门门在完全没看东西的情况下长期报绿。现在 `valueOf` 的规矩改成——名字在 tokens.css 里就必须解析得出值，
解析不出直接红；只有名字压根不是 `--nexus-color-*`（`text-white` 那种 Tailwind 内建色）才允许返回 null，
并用三条断言把这个边界钉住（`text-bg-0`→`f7f8fb`、`bg-brand`→`5b6cff`、`text-white`→null）。

那 194 处**今天不动**：产品里没有任何地方把主题写到 `dark` 以外（`app/layout.tsx` 钉死），
为跑不到的界面重排 194 条 class 属于投机。但豁免不能靠一行注释维持，所以新加了一道**会自查前提的门**：
它每次运行都去 `apps/web/src` 找"把 `data-nexus-theme` 设成非 dark 的写法"，找到就把这笔账当硬缺陷判红，
找不到就只钉住"读数仍不及格"这一事实（若有人已修好，它会红并提示把硬门打开）。
变异臂实测：临时塞一个 `setAttribute('data-nexus-theme', t)` 进去，门当场红出三条读数并给出 -ink token 的修法。

看图复验（`.scratch/shots-lighttheme.mjs` 强制浅色后拍首页／Studio／市场，控制台无报错）顺手修了两处门看不见的：
首页导航排在 820px 容器里放不下，flex 把中文链接从词中间切断（"全平台搜/索"）→ `flex-wrap` + 每条链接
`whitespace-nowrap`；Studio 左轨按钮按设计只画标签首字（`{item.label[0]}`），读屏只念得出"图"→ 补 `aria-label`
给全名（可见字是全称前缀，2.5.3 同样过）。

notMeasured：浅色主题**在浏览器里**仍没有门（axe 只跑暗色；浅色现在只有 tokens.css 字面值那层兜着）、
"强调色当文字"那 194 处的 -ink token（入口一出现即被上面的自查门逼出来）、
带透明度的底色（`bg-danger/10 + text-danger` 那类真底色是混合结果，按实底算会得到 1:1，只能交给浏览器判）、
收起面板的 axe（名字那半已由 `control-names` 门接住，对比度与其余规则仍没有门）、后台 / 管理界面。

## 首跑抓到的三个真谎（这就是评测存在的理由）

第一次完整跑，7 条结构不变式红了 5 条。逐条归因后：**三条是产品真缺陷，两条是评测自己的错**
（第 6 条不是首跑的，是第二片渲染后无障碍的账——归因写错被自己的修复推翻，一并记在这里）。

1. **§86 颜色指标自比 ≠ 1（产品 bug）**：`paletteOf` 只留 6 个主色，但 share 的分母是
   全部样本——多色图的自比颜色分只有 0.495。修法是除以参考图自己的主色质量
   （refColorMass），并加"8 色条纹图自比必须为 1"的回归钉。
2. **§38 合成链的注释在说谎（产品文档谎）**：renderPixels 的注释宣称"形状/横带位置不变，
   变体是同一张图的换色"，而 hueAnchor 在身份哈希里、整条 rng 流都变——注释描述的
   机制不存在。注释改真；不变式从"变体调色板相似"改钉"锚点色相落进像素"。
3. **DEMO provider 引用了不存在的 token（产品 bug）**：加区块的标题写了
   `{font.display}`，默认 token 目录里只有 font.heading/body/mono——codegen 照发
   `var(--nx-font-display)`，parse 认不回，每次加区块的往返都多一条 set op。改成 `{font.heading}`。
4. **评测语料 bug**：`createWorld` 每个 kind 只建一条，第二条 lore 根本没建，
   「三百盏灯」锚句在语料里是 0 块。改用 `addWorldNode` 补上。
5. **评测自己的引用检查器漏一类**：链式 insert（同批补丁先建后引用）被当成捏造引用，
   9 条假违规。按应用顺序带 `created` 集合重写，并加两条用例钉住"编排不算幻觉、
   顺序反了才算"。
6. **我把自己的读数归因写错了，被下一次测量纠正**：无障碍首跑把壳上 7 处 color-contrast
   中的 2 处（`li`/`p`）说成"作者快照的忠实渲染，领地归作者"。改 token 后 7 处一起消失——
   那两处吃的是平台 `fg-3`，作者投影一条都没进 violations。归因不是读数的属性，
   是读数加上一次因果验证；这一条留在文档里，是因为它是本文件唯一一次被自己的修复推翻。
