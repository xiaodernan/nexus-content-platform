# ADR-0019：公开 API 用「哈希存储的 Bearer 凭据 + 按 scope 划分的读与写」，不复用会话 cookie

日期：2026-09-28 ｜ 状态：已采纳（第一片只读；第二片 2026-09-29 接上写端点） ｜ 关联：§188（MCP / 外部 Agent / 公开 API）、§149、§80、§74、§159、§16、§68

## 背景

M8 要求平台外部的调用方（MCP server、CI 脚本、第三方 Agent）能读到项目的设计文档。
仓库里已有的鉴权只有一种：`nexus_session` 会话 cookie，由中间件签发、`requireUser` 消费，
配套 CSRF 双提交保护状态变更。cookie 这套东西是为「浏览器里的人」设计的，直接拿来给外部调用方用会同时踩三个坑：
凭据会被自动带上（CSRF 的前提）、会随浏览器会话一起过期（CI 跑一次不该有「会话」）、
以及无法按调用方划分能读什么。

## 选项

1. **复用会话 cookie**，外部调用方贴 cookie 进来。省事，但上面三个坑一个都不解决，
   而且等于宣布「平台的 API 凭据就是会话」——一次泄露即一次账号沦陷。
2. **签 JWT 无状态令牌**。服务端不必查库，但随之而来的吊销问题是硬的：
   要做到「吊销即失效」就得引入拒绝列表，那本质上又回到有一张表。
3. **不透明随机串 + 库内哈希**（本决定）。与 `sessions` 同一口径（§80：库里从不存明文），
   每次调用查一行，吊销即生效，签发与吊销都有账可查。

## 决定

- 表 `api_tokens`（迁移 0018）：`token_hash` 存 SHA-256，唯一索引建在哈希上；`hint` 只留随机段前 8 位用于在列表里认哪一把；
  `revoked_at` 用时间戳而不是布尔，行不删；`user_id` 上 `ON DELETE CASCADE`（人注销，凭据跟着没）。
  `scopes` 用 text[] + CHECK 而不是 pg enum，与 §133 的 `users.plan` 同一个理由：加一格只改约束，不重建类型。
- 明文前缀 `nexus_pat_`，随机段 32 字节十六进制。鉴权时先按前缀分流，
  所以「有人把会话 cookie 当 API 凭据用」这件事能报出准确的那一句，而不是「鉴权失败」。
- 所有 v1 端点只经 `authorizeApiRequest`：Bearer 解析 → 鉴权 → scope → 每凭据每分钟限流。
  路由里不许自己重复这几步——§74 的教训是「一条路管一条路，就等于两条路各有一套规矩」。
- scope 名单第一片只有两格（`projects:read` / `design:read`），因为当时只有两个真端点执行它们；
  第二片加上 `design:write`。原则没变：一格名单对应一个真在执行的端点，不预先列"以后可能用到"的格。
  名单在 `@nexus/schemas` 的 `API_TOKEN_SCOPES`，库里的 CHECK 与端点里的实际调用是同一件事的三处写法，
  由 `apps/web/test/api-tokens.test.ts` 交叉比对（三处不一致就红）。
- `last_used_at` 写入按分钟节流：一个读接口不该因为「想知道谁在用」而变成写接口。
  界面上这一列因此标成「最近使用（分钟级）」。
- v1 在第一片只有读。第二片接上 `PATCH /api/v1/projects/<id>/design`（见下一节），
  而 scope 与方法**按位置配对**这条由测试钉住：读 scope 只许挂在 GET 上，写 scope 只许挂在写方法上——
  一个用 `design:write` 的 GET 就是"读接口能改文档"，而界面上写的是"补丁要走 PATCH"。

## 第二片（2026-09-29）：写端点发的是补丁，不是整份文档

这一格与 Studio 自动保存那条路唯一的实质差别就是**发的是补丁**：自动保存说的是"客户端认为这一版就是全部"，
而公网调用方没有资格替服务端决定"其余的都不存在了"。补丁落在服务端此刻那一版文档上。

- **读—改—写在一个事务里**，且 `pg_advisory_xact_lock` 取在读**之前**（与 ADR-0016 同一把锁、同一口径）。
  锁放在读之后等于重新打开那个窗口：两个并发请求各自读到同一版，后写的悄悄吃掉先写的。
  集成用例为此让同一枚凭据并发发两次 PATCH，并要求两个节点都在。
- **一条 op 打不到就整份不写**（409 `ops_skipped`）：写一半比不写更难查，调用方拿到 200 会以为改完了。
- **打完补丁的文档过的是 Studio 保存那道同一扇规模门**（`parseDocument` / ADR-0015）。
  写端点绕开它，公网这条路就成了"想存多大就存多大"的后门，而那道门当初就是为了挡这个才挪到整份文档上的。
- **带走东西的 op 一律拒**（`remove` / `removePage` / `removeToken` / `removeAsset` / `removeComponent` → 409 `approval_required`）。
  §74 那张门的原语义是"有人看过那一版才交回"，而 API 这一侧没有人可以点批准，所以这里是**拒**不是**挂起**：
  挂起等于替一个不在场的人保留"再批准一次就能删"的期望。每次被拒都往 `audit_events` 落一行 `allowed:false`（§80）——
  响应是瞬时的，账不是；拿别人的项目 id 递补丁同样留行。
- **报文在门口就收紧**：`summary` 必填（一次外来的写入要能在历史里读出"谁为的是什么"，否则那条快照只是噪音）、
  `ops` 至少一条（空补丁照样落历史、重切语料，却什么也不改）、一次最多 200 条
  （内部 AI 的上限是 4000，因为它在同一个进程里；公网一个请求不该让服务端把整份文档反复拷 4000 次）。
- **限流分两桶**（读每分钟 120 / 写每分钟 30），数字在 `@nexus/schemas` 的 `API_TOKEN_RATE_LIMITS_PER_MINUTE`，
  界面与测试读同一份，不各抄一个。写比读低是刻意的：一次写要改文档、落历史、重切语料。
- **历史落在事务外面**：写提交成功后建一条 `source:'ai'` 的快照并带上这份补丁的清单，
  Studio 历史面板按 §151 展示它的 diff。这一步（以及语料同步、审计）失败**不把请求变成 500**——
  文档已经改了，报 500 会让调用方重发一份 `insert` 补丁，那是两条节点而不是一次幂等写；
  没成的那一步原样列进 `warnings`。

## 后果

- 好处：吊销立刻生效且可解释（401 带着吊销时间）；凭据可按调用方发、按调用方撤；
  读路径与浏览器会话彻底分开，CSRF 的适用范围也写清楚了（cookie 会话内的状态变更仍要 CSRF，
  见 `/api/account/api-tokens` 的 POST；Bearer 端点不需要，第二片的 PATCH 同理——凭据要人贴进请求头，
  跨站的表单打不出这一格）。
- 代价：每次调用一行 SELECT（限流在前，量级可控）；明文一次性显示，丢了只能重发——
  这一点必须在界面上说清楚，否则用户会以为「刷新一下还能看到」。
- 已知限制：设计文档整份返回、没有分页也没有字段裁剪，**这一句现在有实测的数**（2026-09-30，
  `scripts/perf-public-api.mts`，生产构建走真 HTTP）：4008 节点的那一份是**解开 3293KB / gzip 103KB，
  每节点约 841 字节**，一次 GET 中位 513–951ms，一次 `insert` 中位 1369–1597ms（数字与口径在 `docs/PERFORMANCE.md`）。
  报文大这件事本身已经被编码协商抵掉了 97%（第四片：`apiJson` 在 ≥1KB 且调用方收 gzip 时压，
  线上实测 `content-encoding: gzip`、同一份内容 3293KB → 103KB），但**"一次读要反序列化整份文档"
  这一条没有变**，10000 节点档会翻倍到约 6.6MB 且仍然没有分页；
  写只有 `design:write` 这一格（改文档），**没有项目创建/删除/发布的端点**，也没有 `projects:write` 那种一格管一切的 scope；
  读有 `api_access_buckets` 这本账（第三片）：按分钟合并、只到（端点, 项目）这一层、只留 30 天、不记报文内容，
  `last_used_at` 仍是那一个总信号。
- 验证到哪一步：这个文件现在有 4 条 @smoke，三片各一条加游客一条（`npx playwright test e2e/api-tokens.spec.ts`
  **4/4 绿**）。读那一寸（第一片）：签发 → 页内真 fetch 200 → 缺 scope 403 → 吊销后 401 → 刷新后整页找不到明文，
  截图 `screenshots/api-tokens-issued.png` / `api-tokens-after-reload.png`。写那一寸（第二片）：面板那颗按钮留下的节点数
  与随后 GET 回来的一致、`remove` 得 409 而文档一个节点都没少、只读凭据的 PATCH 得 403 且界面原样贴出那句话、
  缺 summary 得 400，截图 `screenshots/api-write-panel.png` / `api-write-refusals.png`。
  访问账那一寸（第三片）：同一枚凭据三次清单读在面板上不超过两行而合计仍是 3、design 那一格 ×1、
  读过的那一份带项目名、只给清单权限的那一枚账上**只有清单那一格**（那次 403 一行都没留），
  截图 `screenshots/api-access-ledger.png`。
  编码那一寸（第四片）不在浏览器里量，而在**真服务端的线上**：`scripts/perf-public-api.mts` 里的 `wireProbe`
  自己数 chunk（fetch 会透明解压，问不出"有没有压"），要 `gzip, deflate, br` 时回 `content-encoding: gzip`
  且线上 103KB，要 `identity` 时 3293KB——两句都在 `docs/PERFORMANCE.md` 的表里。
  加上 `api-response.test.ts` 26 条（协商表、阈值边界、`content-length` 与体同源、CJK 长度口径、
  以及扫 v1 目录不许再出现裸 `NextResponse.json` 的结构门），
  和 `api-tokens.integration.test.ts` 30 条打真库（2026-09-30 补跑，覆盖改过的三个 v1 路由）。
- 仍未验证 / 未做：10000 节点档的公网读没有量过（`MAX_NODES_PER_DOCUMENT = 20000` 允许它，
  而这一格没有分页，所以那句限度至今只到 4008 这一档）；`PATCH` 那 1.2–1.6 秒花在**哪一段**没拆
  （整份 `loadDocument`、`saveDocument`、语料同步、历史 diff 各占多少还没证据，只有对齐过的两个数）；
  访问账只有"按人 / 按枚"这一种视图，没有全局视图也没有导出；MCP 与外部 Agent 接入那一格还没动。
