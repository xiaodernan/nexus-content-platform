# ADR-0036：Combat Design 这一格吃的是上一格的草稿，改的是数值，产物仍然是草稿

- 状态：已采纳（§52 第二片：Game Design → Combat Design）
- 日期：2026-10-12
- 关联：§52、§53、§112、§113、§16、§159、§160、ADR-0020（编排只读）、ADR-0035（产物的落地形状）

## 背景

§52 那条链的原话是 `Game Design → Combat Design → Level Design → … → Code`。
第一片（ADR-0035）解决了"AI 的产物住在哪儿、谁有权让它落地"。加第二格时同一组问题换了形状：

1. **没有 provider 时"战斗设计"能做什么**？能回答的只有确定性的那一半，
   而 §159 禁的是把那一半说成另一半。
2. **"调进目标带"里的目标带是谁定的**？需求（§52/§53）没写阈值。
   没有写下来的带子，"调好了"这三个字就没有真值——只有措辞。
3. **一份任务里有两份草稿时，「接受」接哪一份**？ADR-0035 的入口当时写死了 `game` 那一步。
4. 上一片的教训还在：披露文字里手写的条数会与数组长度漂移（那片是"四步"，这一片差一点写成"四条目标"，
   而目标是**五条**）。

## 选项

1. **等 provider**（#105）。整格空着，ROADMAP 上 §52 那条链继续是"只到草稿"。
   否：可确定那一半（跑一遍、按规则改数值）今天就能做，不做是拿"另一半月没有"当"这个月什么都不做"。
2. **只做报告，不改数值**（§53 的 Playtest 已经有四种走法的报告）。
   否：那只是把第一格做完的东西再读一遍，链子没有往前走。
3. **把调数值交给面板上的滑块**（人在 Game Studio 里自己改）。
   否：那一格已经存在了，而且它不是 §52 那条链——链的意义是"上一步的产物是下一步的输入"。
4. **本决定**：在 `packages/game-model` 里放一层**写死的规则**（目标带、杠杆、上下界全是常量），
   吃上一步的草稿，一轮一轮试、只保留"读数变好且没把已达标的挤破"的改动，产物**还是草稿**存进这一步的结论行。

## 决定

### 规则层是常量，不是判断

- `COMBAT_GOAL_ORDER` 五条（有路可通 / 不是一照面就结束 / 赢家要付出代价 / 站着不动不能赢 /
  一直躲不该几秒就死），`COMBAT_RULES` 是它们的阈值与步长上界，`COMBAT_LEVERS` 七条。
  **界面上与 notes 里都写清：这些阈值是这一格自己的定义，不是需求里写好的验收标准。**
- 只动数值：`health / damage / detectionRange`（计划里的字段名是 `senseRadius`，映射表只有那一处）。
  不改规则、不加实体、**不动布局**——布局是 §51/§54 的真值，这一格没资格改它。
- 读数不是估的：每一轮改完都重跑 §53 那份定种子报告（四种走法、跑的是 `rpgStep`）。
  因此**四种走法不是穷举**：0 种通关不等于不可能，五条全达标也不等于好玩——这两句话进 `COMBAT_DESIGN_LIMITS`。
- 这一格是纯函数：不读时钟、不碰库。`at` 由 web 层注入（`{ at: new Date().toISOString() }`），
  所以同一份草稿两次跑出来的数值表逐键相同，只有时间戳跟着这次跑动走。

### 撤回也是一种产物

- 保留条件只有一条：`improved && broke.length === 0`。**读数变好但把另一条已达标的挤破，照样撤回。**
- 撤回的轮次留在 `rounds` 里（`kept: false` + `revertedBecause`），notes 逐条点名是哪一条杠杆破了哪一条目标。
  只报"改了 3 处"等于把试验过程抹掉，而过程才是这一格可读的部分。
- 撤回的那条杠杆标成用尽（`spent`）：同一杠杆反复试会在轮次里绕圈。
  结构上有一条杠杆**永远不可能改善它的目标**（`idle-not-win` 的唯一杠杆是加宽敌人察觉半径，
  而"站着也能赢"的成因是触发器贴着玩家——那是布局问题，数值动不了它，读数一动不动）。
  这条写在用例（`站着也能赢是布局问题：这一格只动数值，动不了它就原样交回`）与注释里，
  不偷偷把那条目标删掉让数字好看。

### 编排与接受入口

- `combat` 是第六种步骤，`dependsOn: ['game']`，`requires: 'game.write'`，产物 `combat_spec`。
  **拿不到上游草稿就直接失败**（`throw`，计划里这一步 `failed`），不另编一份设计来"调"——
  这一步没有输入就没有输出，这是 §159 在这一格的具体形状。
- 产物仍然只是草稿，存在这一步自己的结论行（`result.steps[].draft`），ADR-0035 那条线一字不动。
- 接受入口从写死 `'game'` 改成按 `stepId` 选：**给了就点名要那一步的那一份，没给就取这份任务里
  最后一个留了草稿的步骤**（链末，也就是调过的那一份）。
  点名的那一步**必须真留了草稿**——不猜、不退回别的步骤去拿一份"差不多的"，
  那种退回会让界面上写着 combat、库里进的是 game。
- `createOnly` 不变：一次作业有两份草稿，但项目只能有一份游戏设计。
  第二下点击必然 409，而服务端那句原因照实说（"已经有 XX 这一份，接受不会覆盖"）。
- 拒绝审计带上 `stepId` 与当时真能接受的清单 `available`：
  证据要能回答"他点的是哪儿、那时候有什么可选"，而不是只回答"有人失败过一次"。
- 披露文字的条数**全部从数组派生**（`${COMBAT_GOAL_ORDER.length}` / `${COMBAT_LEVERS.length}`），
  测试也用同一份数组来钉，不用字面量——这样"五条目标却写着四条"这一类漂移在写的那一刻就红。

## 怎么被钉住的

- 纯层 26 条（`packages/game-model/test/combat.test.ts`）：目标与杠杆的**表形状**（每条目标都有杠杆、
  id 顺序、字段映射）、五种走法的读数逐条对号、保留/撤回两种结局各自有独证（sole witness）、
  确定性（换 `at` 才动时间戳、同一份输入两次逐字节相同）、限度三句话。
- 七条变异臂（行为性，逐条写下预期红）：**A** 阈值 18→4 秒红 13 条 / **B** 加厚不再成套红 11 条 /
  **C** 保留条件去掉 `broke.length === 0` 红 1 条 / **D** 写时间戳改读时钟红 3 条 /
  **E** 没有玩家也照样往下改红 1 条 / **F** 撤回后不标记用尽红 7 条 / **G** 去掉 `improved` 红 6 条。
  读数与"为什么 C 只红一条"记在 `docs/TESTING.md` 2026-10-12 那一格：**C 第一轮是幸存者**，
  因为当时所有被撤回的轮次都恰好 `improved === false`（读数变差），
  `broke` 那一半从来没有单独被观察过——补了"免费通关"那一份 fixture 之后它才红。
- web 层八臂（`W1`…`W8`，读数是量出来的，见 `docs/TESTING.md` 同一格）里 **W7 也是一条幸存者**：
  把"达标条数"报成"总条数"那种谎在全绿那份 fixture 上没有可观测后果（调完正好 5/5，两个数相等）。
  补的不是注释而是**一条用例**：注入一份**没有玩家实体**的上游草稿（`tuneCombat` 走 `not-runnable`），
  达标条数 1、总条数 5，用例先钉住"这两个数必须不相等"再钉读数——重跑 W7 才红出 `expected 5 to be 1`。
  这条用例同时钉住了另一件界面上的事：**跑不起来的设计要照实说"一轮没调、0 处改动"**，
  而不是写成"调过 7 轮"（§159 在这一格的形状）。
- web 层其余读数：编排集成测多三条（combat 的计数与摘要与库里那份不同；上游没草稿时 combat 是 `failed`
  且说的是"没拿到上游草稿"；上游那份本身开不了场时 0 轮 + 达标条数按那份文档重跑一遍算出来）、
  接受集成测多两条（`stepId` 点名给哪一步就写那一份；点了没草稿的步骤 409 且话里点名哪些步骤真有草稿），
  纯层多两条（combat 一开始不就绪、game 失败只带走 combat）。
  **`dependsOn` 是这一步唯一的输入通道**这件事被 W6 量过：把它摘掉，执行器给这一步的 `upstream` 就是空的，
  守卫抛、整轮 `failed`，14 条断言在不同层面上各自红（读数与逐条归因记在 `docs/TESTING.md`）。
- e2e `@smoke`：真浏览器里点的是 `combat` 那一格，落库的实体表与库里 combat 那一步的草稿逐字节相同；
  再点 `game` 那一格被拒且库不变（`agent-accept.png` / `agent-accept-refused.png`）。

## 后果

- 好的一面：链子往前走了一格，且这一格的输出**能证明它改过数值**（与上游那份不同一张表），
  而"改坏了"的尝试也留在报告里；阈值是写死的、被点名是写死的，所以没人能把"五条全达标"读成"这游戏好玩"。
- 代价：阈值是我定的。定得对不对不由这一格回答——它回答的是"我按这五条跑了一遍并留下了账"。
  将来接 provider（#105）时这一层的价值不是被替换掉，而是继续当**裁判**：模型可以提议改动，
  但保留/撤回的判断仍然来自这份常量表。
- 代价：一次作业有两份草稿，`createOnly` 又只让落一份，所以"原始 vs 调过"的对比今天只能靠
  先接受一份、去 Game Studio 删掉、再接受另一份。要做的是 §54 的存储形状（一项目多份文档），不是这里的入口。
- 未决：链的第三格（Level Design）与最后一格（Code，产物要能下载、**不得在主机执行**，§81）仍欠。
