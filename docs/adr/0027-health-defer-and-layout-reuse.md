# 0027 — 健康体检先防抖与复用，不做假增量

日期：2026-10-03 ｜ 关联：§147 热点路径、§178 项目健康、§179 发布门禁

## 背景

`HealthRail` 与 `PublishPanel` 都在 `useMemo` 里裸调 `analyzeHealth(state.document)`：
无防抖、不传已算好的布局。10k 节点全量体检约 150–350ms（排版 + 全量
validate/lint + 全树 static walk），于是：
- 健康页签开着时，每敲一个字都同步跟一次全量体检，输入卡顿；
- 发布面板**合着时也在算**——用户根本没在看门禁，却为每一次 commit 付全量账。

PERFORMANCE.md 那句"改成防抖或增量"指的就是这里。要定的是：防抖做到哪一层，
布局复用的边界在哪，以及什么叫"假增量"而不能做。

## 选项

1. **真 per-node 增量**（否决，本片不做）。把上一次报告里"没碰到的节点"的
   findings 留下来，只重算受影响节点——听起来最彻底，但 findings 的上游
   `validateDocument` / `lintDesign` 是整档 API，没有按节点跑的入口。
   不先重构那两个，所谓的"增量"只能是"全量跑完再过滤"，一分钱没省，
   还多一层合并逻辑可错。记为后续 epic，不在本片假装。
2. **防抖 + 布局复用 + 懒算**（选这个）。三刀都不碰判分逻辑：
   - 健康栏用 `useDeferredValue` 延迟**整个快照**（文档/布局/视口同版本，
     不存在"旧文档配新布局"的错配），连续按键只画旧读数，停顿后跟上；
   - 把已算好的当页布局传给 `analyzeHealth({ layouts })`（该参数早就在，
     就是为这一天留的），单页文档省掉内部全页重解；
   - 发布面板闭合时不算，打开那次仍是全量——门禁不读旧数。
3. **WeakMap 按文档身份跨调用方缓存报告**（暂不做）。它只省"同文档被两个面板
   各算一次"的那点，而 defer + 复用已经拿掉大头；多一层缓存多一处"布局变了
   报告没变"的风险，不成比例。

## 决定

- **只有 design 视口的布局才能复用**。断点视口的几何是按断点宽度裁过的，
  拿它喂门禁会把"响应式换行后的尺寸"当成设计尺寸判，off-canvas 与 tap-target
  全错——省出来的毫秒不值得一次误判。条件写死在调用点，不依赖调用者记得。
- **发布面板的懒算以 `open` 为门**：`useMemo` 里 `!open` 直接回 null。
  面板常驻挂载（不在 tab 门后），不加这一格，防抖只 cover 健康栏那一路。
- **复用路径必须有等价性单测**：外部传入布局与内部求解的报告 `toEqual`，
  钉在 `health.test.ts`。复用改变判分的话，它是第一声警报。
- 不动 `analyzeHealth` 本体：它的签名早已支持 `layouts`，本片只是第一次
  有调用方真的传。validate/lint 的增量化是下一轮重构，不在这里开口子。

## 后果

- 连续输入时健康栏最多落后一次停顿；发布面板打开那次仍是全量当前数。
- 单页文档的健康重算省掉整块排版；多页文档只省当页，其余页照旧内部求解——
  如实，没有"全增量"的说法。
- 仍然欠的：validate/lint 的 per-node API（真增量的前置）、Web Worker 跑
  layout/health（主线程减负）、生产构建复测。
