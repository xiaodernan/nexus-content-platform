# 0084 - 顶栏弹层在 390：贴视口的浮层、≥24 的目标，以及「Tab 离开即收起」而不是焦点陷阱

日期：2026-11-05

## 背景

八片 `§85` 的「仍欠」里挂着同一句话：**「390 下弹层落点与触达尺寸、焦点陷阱仍在」**
（第三十六 / 三十八 / 三十九 / 四十 / 四十一 / 四十二 / 四十三片）。这一句话此前一次都没量过，
而它是可量的：面板是顶栏里一个绝对定位的卡片，视口 390 只是一个具体数字。

先量，不改：

- 发布弹层 `w-[440px]`，触发键的右边缘在 343.3 ⇒ 面板左边缘 **-96.7px**，96.7px 在视口外。
- 导出弹层 `w-[360px]`，同样锚在触发键上；390 下勉强不越界，但没有任何一条读数能保证。
- 两块弹层里各有一颗 `收起`：**28×21**，低于 WCAG 2.5.8 的 24×24。
- 焦点从面板最后一颗控件按 Tab：焦点落到面板背后（发布 → 「预览」链接，导出 → 「发布」键），
  **面板仍然开着**。读屏用户听到的仍是面板里的内容，键盘焦点却已经在别处。

## 选项

1. **把弹层做成模态对话框**：`role="dialog"` + `aria-modal` + 背景 `inert` + 焦点陷阱。
   语义最完整，但这两块是挂在顶栏触发键下的轻量卡片，不是覆盖全页的模态；`aria-modal`
   没有 `inert` 配合就是一句假话，而给整棵树做 inert 再恢复、还要把 Escape 后的焦点
   从 inert 里捞回来，改动面远大于这一片要解决的问题。
2. **什么都不做，只在文档里承认它不是模态**。焦点跑到背后而面板还开着的那个现场仍然在。
3. **非模态 + 离开即收起**：不声明模态、不做陷阱；但 Tab 从最后一颗控件离开（或在触发键上
   Shift+Tab）就收起，焦点回触发键。**选定。**

## 决定

- **<520px 的浮层贴视口**：两块面板加
  `max-[520px]:fixed max-[520px]:left-3 max-[520px]:right-3 max-[520px]:top-[52px] max-[520px]:w-auto`。
  手机档的锚点从"触发键的右边缘"换成"视口的左右 12px"——触发键在可横滚的顶栏里，
  它的位置本来就不稳定；≥520px 仍是原来的绝对定位，桌面布局不变。
- **宽度夹住**：`w-[min(440px,calc(100vw-24px))]` / `w-[min(360px,…)]` 作为桌面档的兜底，
  窄视口也不会出现一块比屏幕还宽的面板。
- **`收起` 到 24×24**：两块面板同一颗键改成 `inline-flex h-6 min-w-6 items-center justify-center px-1`。
- **Tab 离开即收起**（`use-popover-dismiss.ts`）：
  - 在面板最后一颗控件上 Tab，或在触发键（这一层的第一颗）上 Shift+Tab ⇒ `preventDefault`，
    收起并把焦点放回触发键；
  - 从触发键 Tab 进入面板、从第一颗面板控件 Shift+Tab 回触发键，仍是浏览器默认行为。
- **不声明 `aria-modal`**：面板仍是 `role="region"`。这条决定的措辞是"离开这一层就收起"，
  不是"焦点被关在里面"——两者对读屏用户是不同承诺。

## 后果

- 390×844 实测（`e2e/popover-mobile.spec.ts`，1 passed / 4.5s）：
  发布 **x=12.0 y=52.0 w=366.0 h=239.0**；导出 **x=12.0 y=52.0 w=366.0 h=462.0**；
  两块面板的 `<24px` 目标都是 **[]**；Tab 之后 `inPanel=false / onTrigger=true / panelStillOpen=false`。
  截图 `screenshots/popover-390-publish.png` / `popover-390-export.png` 人工看过：两块都完整落在
  视口里，没有横向裁切。
- **自然红两次**：改之前 440px 面板红在「左侧越出视口 96.7px」；`收起` 未改时红在
  `{"h":21,"label":"收起","w":28}`。两条都不是先写断言再补实现。
- **臂**：把 Tab 分支改成直接 `return`（等于没有离开即收起）⇒ 红在
  「收起后焦点应当回到触发键」。恢复后 1 passed（4.1s）。
- 回归：`a11y-opened.spec.ts` 的发布 / 导出两条 axe 用例 **2 passed (8.6s)**——Tab 进入面板的
  第一停仍是可见性单选 / 第一个复选框，说明这条改动没有把"走进弹层"一并挡掉。
- 仍欠：① **320px** 宽没有单独读数（<520 的贴边策略在数学上成立，但没量过）；② iOS Safari
  与软键盘弹出时的可视高度（`dvh` 与 `vh` 的差别）没有真机读数；③ 面板内容超长时
  `max-h-[72vh]` 内的滚动没有在 390 下量过（当前两块内容都装得下）；④ 焦点陷阱**明确不做**，
  若将来把发布面板升级成真正的模态，应整块换成 `dialog` + `inert`，而不是在这份 hook 上补 trap。
