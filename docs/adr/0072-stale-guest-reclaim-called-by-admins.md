# ADR-0072：过期访客身份由审核员调用式回收，判据是「沉默六十天」，走的是注销那六件事

- 状态：已接受（2026-10-30）
- 相关：ADR-0025（注销账号那六件事）、ADR-0011 / ADR-0022（不养长驻进程）、ADR-0060（guest 自动签发之前的闸）、§137（免注册首次体验）、§159（不许假装有门）

## 背景

§137 起，每一个第一次打开站点的浏览器都会拿到一个 guest 身份：中间件签发会话 cookie，
`requireUser()` 在库里建一行 `guest=true` 的用户。会话是 30 天滑窗（人一来，还没看内容就先续期）。
**没有任何东西负责让它们结束**——第二十六片把这笔账记在 ROADMAP 上：「库里现存的 guest 行——
谁来扫、留多久、怎么不误伤正在用的浏览器会话」。

开工前库里的形状（2026-10-30 活体读数，本地开发盘 `nexus`）：

| 读数 | 值 |
| --- | --- |
| `users` 总行 | 1811（其中 42 行已软删） |
| 未软删的 guest | 49 |
| ├ 有活会话 | 47 |
| ├ 只有过期会话 | 1 |
| └ 一条会话都没有 | 1 |
| guest 会话行 | 48，过期时刻从 2026-10-29 铺到 2026-11-28 |
| 最早的一行 | 2026-09-21 |

**按任何合理的宽限期，今天一条都不够格**（最老的行才一个多月）。这不是"所以不用做"，
而是"所以这一片的见证只能靠回拨时钟来造"——下面凭证那一节就是这么办的。

指向 `users` 的外键共 **41 处**（同一趟 `pg_constraint` 读数）：`SET NULL` 16 处、`RESTRICT` 5 处
（`projects` / `games` / `worlds` / `characters` / `storyboards` 的 `owner_id`）、`CASCADE` 20 处。
所以"顺手硬删一行"既走不通（那 5 处 restrict 直接报错），也太走得通（那 20 处 cascade 会把别人的
赞、评论、关注一起带走）。

## 选项

1. **常驻定时进程**（cron / worker 每天扫一遍）。否。ADR-0011 与 ADR-0022 已经把口径定成
   "不养长驻进程"；更要紧的是这样一个进程**没有主语**——批量收走身份这件事在审计里那一列 `actor_id`
   该填谁。填一个系统账号等于把"谁决定的"这个问题永久推迟。
2. **请求路径上顺带扫**（`requireUser()` 有概率触发一次清扫）。否。它把延迟与行锁随机派给真实用户，
   而且判错一次的爆炸半径等于流量：一次误伤在日志里长得像"今天运气不好"。
3. **一次性迁移脚本**。否。判据是时间，清完还会再长出来；迁移是"改变形状"的工具，不是"维持不变式"的工具。
4. **调用式清扫**：一个管理端点 + 后台面板，由审核员点；同一份域函数留给运维脚本用。**选它。**
   主语天然存在（点的那个人）、爆炸半径天然有界（一次点击 ≤ 一个 batch）、且"有没有在跑"这件事
   在审计里数得出来。
5. **硬删**。否。见上面那 41 处外键；且 ADR-0025 决定一早就为"注销"定过调——软删、`email` 与 `handle`
   原样留着，审计里那句"这个人做过什么"要指得到人。

## 决定

**一、判据是沉默，公式写在库里而不是界面上。**

```
guest = true AND deleted_at IS NULL AND role = 'creator'
  AND created_at < now - grace
  AND NOT EXISTS (会话 where expires_at > now)
  AND (max(会话.expires_at) IS NULL OR max(会话.expires_at) < now - grace)
```

`grace` 默认 30 天 ⇒ 从这个人**最后一次打开页面**算起约 **60 天**（会话本身活 30 天 + 再等 30 天）。
界面上说"两个月"而不是"30 天"，因为后者会让人拿会话寿命去减，算出一个短的。
`created_at < cutoff` 那一条看着被会话判据包含了，它挡的是 `createUserSession()` 里
"插入用户行"与"插入会话行"之间那一瞬——一个刚出生的 guest 在那一刻正是"零会话"的形状。

**二、四道护身符把人在候选里剔出去**，不是"照样收走但提醒一下"：

- **认领过**（注册把 `guest` 置回 false 并写 `claimedAt`）：注册这个动作本身就是护身符；
- **`role ≠ 'creator'`**：万一有人手改库把一个 guest 提成了审核员，那行不该被一个清扫收走；
- **名下有已发布作品**：注销是本人决定时，"作品留下、作者名换成「已注销的用户」"是 ADR-0025 决定二；
  但自动回收不是他的决定。让一个从没登录过的匿名身份把公开页上的作者名换掉，
  是**替读者做了一件没人授权的事**——这一格宁可不收，留给一个能负责的人；
- **还握着有效 API 令牌**：guest 也能建令牌，那说明这个身份正在被脚本用，"过期"这话不成立
  （已吊销的不算）。

**三、收走＝执行 ADR-0025 那六件事，与自助注销同一个执行体。**
`account.ts` 里那一段抽成 `runAccountDeletion(tx, userId, at)`，两条路共用一份实现。
第二条路最容易出的错是"少做一步"（打了 `deletedAt` 但会话行还在），共用实现让这种漂移在编译期就露出来。
一批一个事务：中途失败这一批一条都不写。

**四、锁上再判一次。** 扫描与执行之间隔着几毫秒到几秒，那里面够一个浏览器回来。
`select … where id = $1 and <同一条谓词> for update` 锁的是 `users` 那一行；Postgres 对子表的
插入/更新会向父行取 `FOR KEY SHARE`，与 `FOR UPDATE` 冲突 ⇒ **并发的会话写入排在这把锁后面**，
窗口是关在库里的，不靠两边时间戳对齐。拿不到行＝此刻不算了，`skippedUnderLock++` 跳过它，
不抛错——一个回来的浏览器不该让整批回滚。

**五、不用确认串。** 注销要逐字输入 handle，那道检查证明的是"坐在键盘前的人认得自己的标识"。
被回收的那个人**不存在**，而程序自己能算出那串字。用算出来的确认串去满足一道自己设计的检查，
是假装有门（§159）。授权改放在够得着的地方：`isAdmin(actorId)` 判在域里（与 `setUserRole` 同一口径，
下一个入口照抄才不会被漏掉）+ CSRF + 按人 6 次/10 分钟的限流 + 一次最多 200 个 + 一行 `user.reclaim` 审计。

**六、默认 dry run。** 一个不带 body 的 `POST` 最安全的解释是"先数一遍"。
默认值写成 `false` 的话，任何一次手滑的 curl 都是一次批量删除。
读会话用 `currentUserOrNull()` 而不是 `requireUser()`：后者会替没有会话的请求现造一个 guest，
而这个端点恰恰拿 guest 开刀——探测一次就白得一个身份，等于清扫自己造待收的料。

**七、界面上第一份数字是服务端算的，按下去之前再数一遍。** 面板挂在 `/admin/users`（只对审核员渲染），
「重新数一遍」与「收走这 N 个」打的是同一个端点，只差 `dryRun`。
读数、列表行数、按钮上那句「收走这 N 个」必须是同一份快照里的同一个 N。

**八（2026-10-30 补）：一次点击的范围＝这一屏上勾着的行，不是"此刻全库够格的"。**
端点接一个可选的 `ids`（点名的那几个人）；面板每行列一个勾选框，**默认全勾这一屏列出来的候选**（前 8 行），
一个都不勾时那颗按钮直接禁用。发出去的是 `ids`，所以「收走这 N 个」那句数与真正会被动到的人是同一份清单。

- **点名不是钥匙**：点到的 id 仍然逐个在 `for update` 锁下过**同一条判据**（决定一那行谓词 + 决定二那四道护身符），
  不成立就 `skippedUnderLock++` 跳过。审核员的鼠标不能把一个还握着有效令牌的人变成够格的。
- 报文层先挡畸形：`ids` 必须是 UUID 数组、去重后再钳上 200；不合法的报文 400 且**挡在限流闸之前**，
  不吃那 6 次/10 分钟的额度（否则一个手滑的脚本就能把审核员的额度耗光，让真正要做的那一次被 429 挡住）。
- 回执那句数由服务端算：`点名的 N 个里收走了 M 个，K 个此刻不够格没动`；界面原样贴出来，不自己数第二遍。
  审计 `detail.named` 分得出一轮是指名道姓收的，还是照整份清单收的。
- 勾选**是范围，不是确认**——刻意不做成"必须先勾满才允许执行"那种门槛：真正的门是 CSRF、审核员身份、
  按人的限流、一次最多 200 个与那一行审计。加一层纯界面的"证明你想清楚了"只会让人以为点了没反应是页面的错。
- **这一条真正的收获在测试那一侧**：有了 `ids`，常驻 e2e 才敢点真执行（它只勾自己造的那两行，
  别人的身份一个都不碰）。于是决定七那格——"真收走之后界面必须跟着换到新读数"——第一次有了常驻门。
  此前它只由 `scripts/capture-guest-reclaim.mts` 手跑见证过（第二十九片臂 A17：摘掉那两行 `useEffect`，
  单元与 `tsc` 都还是绿的）。现在摘掉它，`e2e/guest-reclaim.spec.ts` 第二格就地红。

**九（2026-10-30 补）：一屏装不下的那些，要数得出来、翻得过去，而且翻页不扩大范围。**
决定八把范围收成"这一屏勾着的行"，代价是屏幕上只看得见 8 行。这一片补的是那一屏之外的部分。

- **翻页是客户端在同一份快照上切窗口**（`reclaim-state.ts` 的 `pageWindow` / `pageCount` / `clampPage`）。
  服务端那边一次读的仍是一份完整清单，点下一屏不发请求：这样"第 2/3 屏"和"够格 19 个"说的是同一时刻的同一份数据，
  不会出现翻过去之后行数对不上读数。越界的屏号被 `clampPage` 折回最后一屏，**不切出空表**——
  空表加一句"收走这 0 个"会让人以为页面坏了。
- **换屏必清零点集**（`goPage` 里那句 `setPicked(null)`）。勾选的含义从来是"这一屏上勾着的行"；
  把上一屏那 8 个 id 带过来，跟新一屏的 8 行一取交集就是空集，于是那颗按钮变成"收走这 0 个"，
  而人真正想收的是眼前这一屏。这条是决定八那句"读数、行数、按钮那句数同源"在翻页后的延伸。
- **两句话不能混成一句**：「这一屏之外还有下一屏」（可以翻过去点）与
  「这份清单一次装不下、翻完也看不到剩下的那些」（`moreThanBatch`，`batch` 与 `scanLimit` 的墙）。
  前者是界面问题，后者是这一轮真的收不到——把它们都说成"还有更多"，人会一直翻到一个不存在的第三屏。
- **`scanLimit` 从硬写的常量变成可注入的入参**（默认仍是 1000），那句"只数了前 N 个"读的是回执里的数，不是界面上的字。
  硬写时它属于界面，一次改小扫描就变成一句假话；现在它与 `scanTruncated` 同源于同一份快照。

- **这一片捞出一个第二十九片就在的真缺陷**：我在查翻页怎么接的时候撞见路由的 `payload()` 从来没返回 `scan`
  那一份读数——面板写的是 `body?.scan`，于是那颗「重新数一遍」在屏幕上**什么都没换**，只换到一句回执文本；
  `adoptScan` 走 POST 响应那半条分支是死码。而旧 e2e 那句"三处数同源"是**恒真的**：两边读的都是同一份初始渲染，
  所以它从来没检查过任何东西。这正是 §85 说的"门看着装着，其实没接电"。
  现在那一格有了对照组：加载之后往库里种一个人，再点「重新数一遍」——屏幕上的读数必须从 `够格 N` 变成 `够格 N+1`，
  且回执的 `scan.candidates` 里带着那个新 id。摘掉 `payload` 里的 `scan`，第一格就地红（臂 C1）。

## 后果

**得到的**：这笔账第一次有了写入方；"有没有人在扫"在审计里数得出来（`user.reclaim`，带 `sweep:true`）；
误伤半径被四样东西同时框住——60 天的线、四道护身符、一次一个 batch、以及（决定八）一次只收这一屏勾着的行。

**代价，逐条说清楚**：

1. **软删行继续增长**。这一片解决的是"过期身份能被认出来、能被收走"，不是"库里行变少"。
   真要回收存储，得另做一件"注销满 N 天后连行一起清"的决定，而那要先把 41 处外键的归属谈完。
2. **`email` 与 `handle` 占位不变**（ADR-0025 决定一的代价）：同一个邮箱此后不能再注册一个新身份。
3. **被回收的人没有"我不同意"的通道**。他 60 天没来了，也没有邮箱（guest 没有 `email` 列的值）。
   这条是刻意的，但它不因为刻意就变得不真实：唯一的补偿是那道"发布过作品的就不碰"。
4. **它不会自己跑**。今天要让回收发生，得有一个人去点。这是选项 4 的代价，也是它的好处。
5. **`skippedUnderLock` 只在一批内部有意义**：并发里另一个清扫先收走了某个人，这一轮把他记成"跳过"，
   界面上那句话是"锁上再判时跳过 N 个"——不是错误，但人需要读得懂。

**测试与限度**（逐字读数在 ROADMAP 第二十九／三十／三十一片那一节）：域层 27 条 + 路由层 10 条 + 面板纯函数 13 条
+ 常驻 e2e 4 格（2026-10-30 实跑）。e2e 第二、三格**点真执行**，但只点名它自己造的那几行——
所以"真收走之后界面跟着换到新读数"这一格第一次有了常驻门（臂 B1：摘掉 `useEffect` 那一句，
屏幕上那一行就是不走，60 秒超时后红）。第三十一片补的是这个门的另一半：门本身先前是死码（路由不返回 `scan`），
现在第一格用"加载后种一个人"做出对照组（臂 C1）。第三格管翻页：9 个候选分成两屏，
翻过去之后"收走这 1 个"点下去只收站着的那一屏（臂 C3＝换屏不清勾选、臂 C4＝退回不翻页，都会红）。
`scripts/capture-guest-reclaim.mts` 继续跑，
但它的角色变了：不再是那一格唯一的见证，而是**给人眼看的截图**（首屏、收窄的勾选、两次回执、收完的空态）。

## 仍欠

1. **没有"回收前打招呼"那一步**。产品里没有邮件通道，guest 也没有邮箱；真要通知，得先有身份可通知的东西。
2. **审计页上 `user.reclaim` 还没有专门的过滤/展示**（`/admin/audit` 只按 action 名列，一行一行看）。
3. **没有自动排期**。如果将来要自动，先回答"主语是谁"（选项 1 那条否掉的理由还成立）。
4. **一次一批一个事务**：batch 上限 200 是拍的，没量过 200 个人在真库上的持锁时长。
5. ~~**面板接住新快照那一行（`useEffect`）没有常驻门**~~ **已还（2026-10-30，第三十片）**：
   决定八的 `ids` 让常驻 e2e 敢点真执行，那一格现在有了门（臂 B1 实测会红）。
6. ~~**一屏只列 8 行，没有第二屏**~~ **已还（2026-10-30，第三十一片）**：加了屏号与上下屏，
   `>8` 那条截断分支现在既有形状用例也有界面用例（常驻 e2e 第三格：9 个人 → 第一屏 8 行、第二屏 1 行、
   点执行只收第二屏那一个）。**这条只还了一半**：能翻到的是 `scanLimit`（默认 1000）以内的那些；
   比这更多的部分根本进不了清单，界面上那句是"翻完这几屏也看不到剩下的那些"，不是一个可以翻过去的距离。
7. **勾着的行与发出去的 `ids` 之间没有第二道确认**：一次误点「收走这 N 个」是真收走。
   兜住它的是那四样（身份、CSRF、按人限流、审计），不是界面自己——决定八写明了为什么不加第五样。
8. **翻页是在同一份快照上切窗口，不重新问服务端**。当前规模下这是对的（一次最多扫 1000 行），
   但它意味着"翻到第二屏"看到的可能已经不是三秒前的库——真正兜住这件事的还是锁上再判那一道，不是界面。
