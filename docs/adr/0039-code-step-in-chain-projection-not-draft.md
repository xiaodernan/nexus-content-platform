# ADR-0039：Code 那格进编排链——它是投影不是草稿，所以它不留草稿、不进库、也不接接受入口

- 状态：已采纳（§52 链的第四格接进 §112 的编排，配方从七步变八步）
- 日期：2026-10-15
- 关联：§52、§53、§16、§25、§81、§112、§113、§159、§160、ADR-0035（产物的落地形状）、ADR-0038（这一格本身的取舍）

## 背景

ADR-0038 把 Code 这一格做成了**出口**：端点 `GET /api/projects/<id>/game/code`（和 `/zip`）加上
Studio「游戏」面板里那两颗按钮。但那条路读的是**库里那一份设计**——也就是说，作者必须先把
§52 链上某一步的草稿**接受进项目**，才拿得到产物。于是编排链上出现了这样一个断口：

```
context / seo-audit / qa-audit → report      （三份检查与汇总）
game → combat → level                         （三份草稿，都停在任务行里，不进库）
                                             ↑ 链到这里就停了
```

三份草稿都在，投影却在链外。用户在 Agent 面板上能看到"数值调过、位置摆好"的那一份，
却要自己切到「游戏」面板、点接受、再点生成，才知道那份设计投影出来是几个文件、多少字节。
更难受的是**这一格的账没人替作业报**：作业跑完说"八件事都做了"，其中没有"能不能拿走"。

三条约束决定了这一格接进链里的形状：

1. **§16 说设计模型是唯一真值**。链上前三格交回来的都是 `draft`（一份还没进项目的文档），
   而这一格的产物**不是文档**——它是同一份文档的另一个样子。给它也留一份 `draft`，
   就等于宣称"这里有一份新的设计可以接受进项目"，而它其实没有改任何一个值。
2. **接受入口的缺省档位是"这份任务里最后一个留了草稿的步骤"**（ADR-0035 / `pickDraft`）。
   这一格若留草稿，缺省那份立刻从链末的 `level` 挪到投影上——用户点"接受进项目"接进去的
   就不是设计了，而是一份与文档一字不差、却被当成"新设计"写进库的东西。
3. **§159 不许把没做的事说成做了**。这一格不需要 provider，也不需要时钟：投影就是字符串拼接。
   所以它的账只能是**真跑一遍生成器**的读数，不能是配方里的常数。

## 选项

1. **把这一格留在链外**（只留出口）。否：那"跑一次作业"与"这份设计能不能拿走"永远是两句话，
   而 §112 的卖点正是"作业里每一步都留了能对账的账"。
2. **让它也产一份 `draft`**，好让用户直接接受产物。否：产物不是设计（§16），
   接受一份投影进库等于把 `game` 表写成 HTML；而且它会抢走接受入口的缺省档位（背景 2）。
3. **让它把产物写进项目存储**（存成资产文件）。否：这一片没有真文件存储的写入方，
   而且 ADR-0038 定的就是"产物不保存、不覆盖"——设计改一个数重新生成就是新的字节。
4. **接进链，只报投影的读数，什么也不留**（选定）。

## 决定

1. **`code` 成为第八种步骤**（`STEP_KINDS` / `READINESS_STEPS`），`agentKey: 'game'`、
   `requires: 'game.write'`、`artifact: 'game_code'`、`dependsOn: ['level']`。
   依赖写 level 而不是 game：投影的要害是"数值与位置都落定之后这份产物长什么样"。
   `RUNNERS: Record<StepKind, Runner>` 那条纪律仍然生效——加一种步骤忘了加执行方是**编译错误**
   （这一片开发过程中就真红过一次 `TS2741: Property 'code' is missing`）。
2. **它拿的是 level 留在结论里的那份草稿，拿不到就整步失败**，话要说清缺的是谁：
   `code 这一步没拿到上游草稿（level 那一步没留下 draft）……这一格不另编一份再投影`。
   绝不"照着配方现编一份再来投影"——那样投影出来的字节与 level 的成果没关系，
   计划里那条依赖箭头就成了装饰。
3. **它不产 `draft`、不写库**。界面上因此只有三颗接受按钮（game / combat / level），
   缺省那份仍是链末的 level。这一句在 e2e 里钉着：`[data-agent-accept-step="code"]` 的个数是 0，
   而同屏 `[data-agent-accept-step="level"]` 是可见的——"没有"配着"换个步骤就有"。
4. **它报的数是 `generateGameCode` 的读数**：`files` / `bytes` / `entities` / `findings` / `limits`，
   summary 说"投影出几份自包含文件、共多少字节"。`CODEGEN_LIMITS` 那四句**随读数一起进 notes**：
   只报"生成成功"而不报"这是转写、没有 Studio 界面、不联网、不执行任何东西"（§81），
   作业就在替产品撒谎。
5. **这一步不许自己给自己打分**：集成测把库里 `level` 那份草稿拿来**再投影一遍**，
   用另一次调用的 `files.length` / `bytes` / `notes.length` 当分母对账，
   再断一次"同一份设计两次投影字节相同"（确定性 = 没有时钟）。

## 后果

- 作业的报告现在能说"这份设计投影出来是 7 个文件、N 字节"，而这句话与作者随后在「游戏」面板
  点那颗按钮拿到的产物是**同一个生成器**算出来的。要真拿走文件仍然得先接受 level 那份草稿进项目——
  这一步不下载，界面上那句话也写着这一点。
- **链更长，牵连也更长**：level 失败时 code 是 `skipped`（不是 failed——它自己没跑过），
  通知写"1 步失败，1 步被跳过"，进度分子少算它一格。这三件事在执行层各有一条用例，
  不是只有纯层（`agent-runtime.test.ts`）的 `blockedIds` 说了算。
- 配方从七步到八步，`agent.activity` 的条数跟着从 15 变 17。这条**改成派生**
  （`1 + 2 * result.steps.length`），原来写死 15 的版本在加一步时只会红得没有信息量。
- 六臂变异电池（三份套件、对照臂 41/41 全绿）：
  | 臂 | 改了什么 | 红 |
  | --- | --- | --- |
  | A | 拆掉"没拿到上游草稿"那道守卫 | 1（正是守卫那条用例） |
  | B | 让 code 也留一份 `draft` | 3（接受入口的缺省档位 + `available` 清单 + 不留草稿那条） |
  | C | 依赖从 `level` 改成 `game`（接错源头） | 14（这一格真的拿不到 level 的草稿，作业整体 failed，下游六条接受入口用例一起红） |
  | D | 从配方里整条删掉 code | 11（八步全绿、两条新用例、纯层依赖表与终态判定） |
  | E | `counts.bytes` 报 0（summary 仍报真数） | 1（重投影对账那条） |
  | F | notes 里丢掉 `CODEGEN_LIMITS` 四句 | 1（同一处点名"限度必须随产物念出来"） |
  B 与 C 的红都不在"这一格自己"而在**别人**身上——这正是接受入口与依赖链被钉住的证据。
- 第一版电池有一处自己的洞，已修：D 臂的"删完还在"自查读的是**内存快照**而不是磁盘，
  于是永远成立、整臂白跑（`INTERFERED`）。改成读磁盘并给每一臂加一句"写完字节至少有一份不同"
  的自证——**"没红"与"没改"必须分得开**。
