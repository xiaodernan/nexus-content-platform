# ADR-0055：下架只改 `visibility`，**不删那一行** ⇒ 统计不再跟着删

- 状态：**已接受并落地**
- 日期：2026-10-22
- 相关：§168（Analytics）· §57（发布）· §159（不拿假数据充数）· ADR-0009（发布钉住那一刻）

## 背景

ROADMAP 的 §168 那条欠账里写着：

> **取消发布会把这一版的统计一起删掉**——`unpublishProject` 删 `published_projects` 行，
> `publication_visits` 跟着 `ON DELETE CASCADE`（`views` 本来就是这个行为，新表继承了它），
> 要留历史得把粒度改成挂 project_id 或**让下架只改 visibility**。

这句话给了两个办法：**改粒度**（统计挂 project_id）或**只改 visibility**（那一行留着）。
今天选的是第二个，理由不是它省事，而是**它不改任何东西的粒度**。

## 为什么"只改 visibility"是安全的（关键的一条）

库里**每个项目只有一行发布行**：重新发布是**更新那一行**（`version + 1`、`path` 不变），
不是插新行（ADR-0009 那一格）。

⇒ 所以"访客现场"本来就是**跨版本累在那一行**上的 ⇒ 那一行本来就不是"某一版的统计"，
而是"这个作品的累计" ⇒

- 把"删行"换成"改可见性"，**统计的粒度一点没变**；
- 顺带修好了另一个今天就有的毛病：**取消发布再重新发布，版本号会重置成 1**
  （因为那一行被删了 ⇒ `version = (existing?.version ?? 0) + 1` 取不到旧值）⇒
  改完之后版本号接着往上走。

⇒ 改粒度（挂 project_id）那条路反而要动读路径：统计不再挂在发布行上，
分析页就得改成按项目读 ⇒ 那是另一种产品口径（"这个作品" vs "这一版"），
今天没有证据说该换 ⇒ 先不动。

## 三个决定

### 一、`unpublishProject` 从"删行"改成"改可见性"

`published_projects.visibility` 置 `private`（`projects.visibility` 照旧置 `private`）⇒
那一行、它的访客现场、它的通关记录**全部留着** ⇒ 审计与预览状态照旧写。

### 二、"看不见"与"没统计"分开，各走各的判定

- **公开 URL**：`getPublishedPage` 判可见性 ⇒ 已下架的读不到（404）✓
- **采集端点**：`findPublicPath` 判可见性 ⇒ 已下架的**连一行都不写** ✓
  （下架之后还在记访客，那是在给一个没人能打开的页面攒数）
- **搜索 / 主页 / 发现流**：本来就已经显式判了 `visibility = 'public'`
  ⇒ 这一格**顺带验了那个判定是真的**（此前"行存在即公开"这个隐含耦合其实早就断了）

### 三、作者自己仍看得见那一行（标着"已停"）

分析页那一行还在，数还在 ⇒ 作者要能看到自己作品的履历（下架前有多少人看过）。
公开面看不到它 ≠ 作者自己也看不到它 ⇒ 这两件事今天就分得很清（那一列写的就是"已停"）。

## 后果

- **发布行的可见性从此是唯一的公开判据** ⇒ 任何"列出已发布作品"的地方都必须显式判它。
  今天查了一遍：`profile` / `search` / `social`（主页、改编、发现流）**已经**判了 ⇒
  这次不用改它们 ⇒ 但这条纪律要写下来：**别再写"行存在即公开"那种代码**。
- **删除项目仍然是删一切**（软删项目 + 它的发布行 ⇒ 统计跟着走）⇒
  账号注销那一条也不变（人都不在了，留着他的访客数没有意义）。
- **发布行的版本号不再重置** ⇒ 这是顺带修好的（见上）。
- **还欠**：**互动作品**（非游戏）的 completion 事件仍然没有；
  统计的**按版本**粒度也仍然没有（那是"这个作品"的口径，今天一直是）。
