# ADR-0073：Studio 的窄视口——左栏浮层、默认收起与「适应窗口」

## 背景

§85 第二十五片在 390 下第一次量 Studio，拿到的事实是：画布被 `overflow:clip` 裁掉 **678px**
（1280 下也裁 88px），界面上没有任何「适应窗口」，缩放只有 Ctrl+滚轮一条路。第二十七片动手前
先量了根因：**左栏图标 44px + 面板 264px 在窄视口仍是内联的**，390 下画布只剩 **82px**；
即使把缩放压到下限 10%，1440×900 的帧仍有 144px 宽——**在 82px 的视口里，任何缩放都装不进去**。

同一遍读数里还有 23–24 个小于 WCAG 2.5.8 下限（24×24）的应用外壳点击目标：图层树每行的
折叠/显隐/锁定三连（21 个）、顶栏回首页链接、项目名按钮、命令栏的「异步作业」勾选。

## 选项

1. **自动适应窗口**（进入/改尺寸时自动改 zoom）：访客/作者的 pan 与 zoom 是**刻意的视图态**，
   窗口一变就重置会把人正在看的位置弄丢；而且首帧自动缩放到 21% 才看得全，等于默认把设计稿缩成邮票。
2. **窄视口继续内联三栏，只允许缩放**：82px 的画布证明这条路走不通（下限 10% 也装不下）。
3. **窄视口左栏改浮层 + 默认收起，另给一个显式的「适应窗口」**。选定。

## 决定

- **< lg（1024）**：左栏面板 `absolute inset-y-0 left-[44px] z-30` 浮在画布上，不再挤窄画布；
  默认收起（`useState(false)` + effect 在 `innerWidth >= 1024` 时展开——不在初值里读
  `window`，避免 SSR 水合不一致）。图标栏 44px 保留，它是导航。
- **lg+ 行为不变**：仍是内联三栏，进页面即展开，桌面上的肌肉记忆不换。
- **「适应窗口」是显式动作**：浮层按钮 `data-fit-canvas` + 键盘 **Shift+1**（Figma 同款；
  Ctrl+0 常被浏览器自己的"恢复 100%"截走，留作别名）。留 24px 边距，缩放仍受 0.1–4 的闸，
  然后按 `screen = pan + canvas * zoom` 居中。它只改视图态：**不进撤销栈、不标脏、不落库**。
- **24×24 收口**：图层三连、顶栏两处、异步勾选补到 24px 高/宽；门挂在
  `e2e/narrow-surfaces.spec.ts` 的 Studio 面上（390 与 1280 都要 0 个）。
- **画布里的节点不算应用外壳**：`[data-canvas-frame]` 内的元素是**用户文档**（作者自己决定
  按钮多大），平台不为它们担保 24×24；量尺与门都只覆盖外壳控件，这条写进 spec 的注释，
  免得下一片把"用户画了一个 12px 的圆点"当成缺陷。

## 后果

- 390 下画布视口从 **82px** 回到 **346px**；「适应窗口」后帧 **298×186 装进 346×536（21%）**。
- 1280 下 **624×390 装进 672×683（43%）**；两栏外壳的 <24px 目标都是 **0**。
- 修的过程中抓到一条**既存缺陷**：图层树是虚拟列表，窗口按 `clientHeight` 算；面板从隐藏变可见时
  高度是 0，窗口停在 6 行且不会重算。补了 `ResizeObserver`，这是"默认收起"之前没人踩到的路径。
- 仍欠：真机 iOS、横屏/平板、画布**内容**目标的尺寸（不归外壳管）、以及"进入即自动适应"这个
  被否掉的选项是否要作为偏好提供。
