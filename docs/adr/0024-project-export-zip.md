# 0024 — 导出这份 zip：自己写 store、回执走 HTTP 头、导入留到下一片

日期：2026-10-01 ｜ 关联：§144 NO LOCK-IN、§16（模型是唯一真值）、§163 `build.status`、§164 Build complete、§159、ADR-0019（公开 API 的鉴权口径）

## 背景

原文 §144 给了四件事：`export design` / `export code` / `export assets` / `delete account`。
前三件缺的**不是能力**：设计文档读得出来（`loadDocument`），代码生成早就能用
（`generateProject()` 产出 `GeneratedFile[]`），资产的原始字节也取得回来（`openAssetForOwner`）。
缺的是"把它交到用户手里"那一步——在那之前，"作品属于用户"（§145）只写在页面上。

这一步同时卡着另外两句话：§164 的第四类通知（Build complete）以前挂在"没有来源"那张单子上，
理由正是"平台没有会完成的构建操作"；§163 的 `build.status` 也只有发布链路一个生产者。
所以这一格的产物不是"一个下载按钮"，而是**第一个真会走完的构建动作**。

要定的三件事：用什么打 zip、包里的数字怎么到达界面、这一片做到哪为止。

## 选项

1. **装一个 zip 库**（`jszip` / `archiver`）。省事，但为一个"把若干文件并排放进容器"的需求
   多引一个依赖就要多一份供应链要审；而本仓已有手写小协议的先例（S3 客户端、PNG 合成）。
   另外 `jszip` 默认按当前时间打时间戳，"同一份内容两次导出字节一致"这条断言反而要绕它。
2. **走公开 API v1 的 JSON 出口**（ADR-0019 那条）。它给的是模型，不给代码与资产，
   而 §144 要的是"把作品整体带走"。而且那是 token 鉴权的机器接口，不是浏览器里点下来的下载。
3. **自己写一个只支持 store（不压缩）的 ZIP 写入器**（选这个）。
   格式只需要 PKZIP 的最小子集：本地头 + 数据 + 中央目录 + EOCD；不做 zip64、不做目录项。

## 决定

- **只 store，不 deflate**。包里主要是代码与 JSON，体积不是瓶颈；deflate 要额外处理
  "压缩后反而更大"与比特序，收益不抵复杂度。真要压，改 `method` 那一格即可，格式其余部分不动。
- **时间戳固定成 1980-01-01 00:00**。同一份内容每次导出的字节必须一模一样——
  否则没法断言"这份 zip 里有什么"，而"导出的是不是当时那份设计"正是这件事要证的。
  （README 里那句生成时间是**故意**可变的：它是"什么时候导的"，不是内容。）
- **zip slip 在写入侧就判**（`safePath`：绝对路径、`\`、盘符、`..`、空段一律抛）。
  资产名与代码路径都带着用户输入，等解压方去发现就晚了。
- **三样是一次请求的三种勾选，不是三个端点**：`GET /api/projects/<id>/export?parts=design,code,assets`。
  原文那句"NO LOCK-IN"说的是作品整体，把三件拆成三个入口只会让人少导一样。
- **归属在动字节之前判，不属于你统一 404 而不是 403**（与资产取字节同一口径：403 会泄露"这个 id 存在"）。
- **回执走 `x-nexus-export-receipt` 头，不让界面自己数**。客户端要数包里有几个文件就得重新解一遍 zip，
  而"导出完成"这句话不能等到那时才敢说；拿不到回执就**只报字节数，不补一个看起来对的构成**（§159）。
  这与任务 id 走 `x-nexus-task` 头是同一个先例：服务端数过的数字由服务端带出来。
- **库里有一行、存储里的字节取不回来 → 不算导出失败，但要点名**。缺的每一项进 README 的"缺了什么"一段，
  通知按 `warning` 而不是 `success`。作者拿着 zip 走人之后才发现缺图，那时候平台已经没机会告诉他了。
- **包里不放 `.nexus/` 那层机器可读结构**，因为还没有能读它的一方。
  `docs/TESTING.md` 第 12 条（导出 ZIP 含 `.nexus/`、能在干净实例导入还原）**仍然算欠**，
  这一片只结 §144 前三件；`docs/RUNTIME.md` 那句"所有导出必须能被另一个实例重新导入"
  在导入落地之前是一句还没兑现的要求，不是一句现状描述。
- **导出是投影，不是快照**。不含历史快照、分支、撤销栈、知识索引与语料、对话、审核记录——
  这三行限度同时写进 README 与 Studio 面板，不只在代码注释里。

## 后果

- §164 那张"没有来源"的单子第一次空下来。**空单子也要留着那张单子**：
  它留着，下一个人加第五类通知时才有个地方记"这一类还没有来源"；删掉它，
  "没有来源"这件事就又变成只有代码知道的事。页面标题因此是分叉的（0 条时说"都有来源了"），
  而不是"这 0 类还没有真实来源"那种读起来像故障的措辞。
- §163 的 `build.status` 有了第二个生产者，Studio 顶栏那行实时读数从此不必等发布才有值。
- 体积：store 不压缩，4000 节点档那份包的实际字节数记在 `docs/ROADMAP.md` 当日段，
  与 `content-length` 同一个来源。真嫌大再加 deflate，格式不用动。
- 下一片的形状已经定了：读侧要防 zip bomb 与超大条目，`.nexus/` 里要有格式版本，
  导入要在**干净实例**上还原（不是在同一库里复制一份），配额按导入后的字节判。
- `delete account` 仍是这四格里唯一没动的，也是 ROADMAP 明写"判决书在写之前不要动手"的那一格。
