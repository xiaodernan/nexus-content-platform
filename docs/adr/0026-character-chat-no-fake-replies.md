# 0026 — 角色对话不做假回复：DEMO 409，未接模型调用 501

日期：2026-10-03 ｜ 关联：§47 角色对话、§46 角色档案、§159、§24 Agent 名册

## 背景

§47 的"跟角色说话"在 ROADMAP 里写死了一句：**没接真 provider 之前不做假对话**。
但 `5533eba`（Character Agent 对话 API 第一片）为了"把路跑通"，用确定性模板
拼了几句"角色微微颔首"式的回复，还把它写进 `memories`——库里从此躺着角色
**没说过的话**，而调用方拿到的是 200。这违反 §159，且和设计补丁的 DEMO mock
不是一回事：补丁是结构化产物、标着 `capability: demo`、进撤销栈可退；
一句扮演成角色说的话没有"撤销"可言，记忆一旦落库就是真值污染。

需要定的是：DEMO 下这条路由应该是什么形状，以及"装配通了、模型没通"
这个中间态怎么表达才不撒谎。

## 选项

1. **保留模板，但标注 DEMO**（否决）。标注改变不了两件事：① 那句话会被读成
   角色说过的；② 它会落进 `memories`，而记忆是后续所有上下文的输入——
   一句假话从此参与每一次人设组装。标注只管"这次显示"，管不住"入库之后"。
2. **DEMO 409，真接通后 501，通了再 200**（选这个）。409 与 web `/api/ai/jobs`
   在 DEMO 下的行为同一口径（`demo_mode`）；501 说明"人设与上下文装配已就绪，
   差的是 provider 的 chat 调用"，并带回装配规模（personaChars / memoryCount /
   knowledgeChars / contextChars）供调试——不是空等，而是有证据的未通。
3. **一步到位直接调模型**（当时不可行）。ai-service 没有 chat 端点与契约，
   本机没有真 key，写出来验证不了。拆成两片：先开通道（契约 + 端点 + pytest），
   再接 web 调用。

## 决定

- 门禁顺序钉死：401/404（归属与存在）→ 409（DEMO）→ 组装上下文 → 501（未接调用）。
  404 排在 409 前面：不存在的角色不谈"能不能聊"。
- 拒绝路径**不写库**：409 与 501 都不落记忆行。参照审批门的纪律——
  "没发生的事不在账本里留行"，否则"点了但什么都没发生"与"失败了"是两笔账。
- 人设与上下文组装抽成纯函数（`server/domain/character-chat.ts`），空栏位
  （空串/空数组）不占行——检索结果里出现一排"外观：（空）"比查不到更糟，
  与知识切分（§49）同一句话。5 条纯函数单测钉死，无需 DB 可跑。
- 名册保持 13 位不变（§24）：角色对话走按角色 id 的专用端点，不加第 14 位 Agent。
  加名册等于改契约（名册随请求进提示词），而对话不需要"点名 @谁"这一层。
- chat 通道随后落地：zod `AiChatRequest/Response`（唯一权威定义）→ 导出
  `ai-chat-request/response.schema.json` → ai-service `POST /v1/ai/chat`
 （复用 `registry.llm.complete`，空回复判 502）→ pytest 5 条（mock transport，
  无需真 key）。回的是纯文本，不带补丁、不走 §73/§74（对话只落记忆行，
  不改设计文档）。

## 后果

- DEMO 下调对话接口即 409，UI 必须做"需真 provider"的诚实态，而不是聊天框。
  web 路由的 501 是下一片要换掉的那格：真实调用 + 记忆落账 + UI。
- 501 带回的四个规模数是调试口径，不是承诺——模型接上后上下文怎么截、记忆取几条，
  以那一片的实测为准。
- 仍然欠的：reranker 真模型（§93）、知识摄取的向量自动同步验证（需 Docker 恢复后跑真库）。
