# ADR-0075：搜索建议与历史——建议来自真实命中，历史只留在设备上

## 背景

§165 落地时记下的三条欠账里，有一条是「搜索建议与历史」。当时的页面注释专门写明
**不做「边打字边发请求」的假实时**——那句话针对的是"没有真实搜索 API、拿本地列表装实时结果"
的做法，不是否掉建议本身。现在要补的正是这一格，且不能把那条纪律弄丢。

## 选项

1. **服务端记「最近搜索」**：多一张表、多一份个人数据、多一套访问控制；跨设备同步那点价值
   抵不上"搜索词会被平台记住"的代价。否。
2. **向量/模型生成"相关搜索"**：本机没有 embedding provider，接上也是 DEMO；而且"相关搜索"
   天然不可验证——建议里出现一个搜不到的词，比没有建议更糟。否。
3. **建议 = 真实命中的前几条（复用 `searchPlatform` 的可见性判定）+ 历史存 localStorage**。选定。

## 决定

- **`GET /api/search/suggest?q=`**：`perGroup=2`（九组最多 18 条，取前 6），每条带 `group`/`label`/
  `href`。查询与可见性**不是另写一份**：直接调 `searchPlatform`，所以「建议里有的，结果里一定有」。
  返回 `cache-control: no-store`；按 `IP + 用户` 限流 120 次/分钟（自动补全最容易被打字脚本放大）。
- **键入防抖 250ms + 中止上一发请求**：慢响应不会盖掉新输入；两个字符起才请求，与结果页的
  `MIN_QUERY` 一致。
- **combobox 语义**：`role="combobox"`、`aria-expanded`、`aria-controls`、`aria-activedescendant`；
  ↓/↑ 移动、Enter 打开选中的那条、Esc 收起、**Esc 之后 ↓ 重新打开**（收起不等于作废）。
- **历史**：`localStorage['nexus.search.history.v1']`，规整（去空白/压空格/80 字）、同串忽略大小写
  只留最近一次、最多 8 条；逐条 × 删除 + 一键清空；坏 JSON / 配额满一律静默降级。
  挂载后才读（SSR 没有 localStorage），避免水合不一致。
- **没有 JS 也能搜**：表单仍是原生 GET；建议与历史是增强。

## 后果

- 每次键入（防抖后）一次 9 组 × 2 条的查询，而不是结果页的 9 组 × 8 条；限流挡住脚本。
- 历史不跨设备、平台看不到搜过什么——这一条写进页面文案，不留给用户猜。
- 自然红一次：第一次跑 e2e 时 Esc 之后 ↓ 不再打开列表（组件只在 `open` 时处理方向键），
  门当场红在 `aria-activedescendant`——修的是行为，不是断言。
- 臂：把建议标题改成固定串（`热门推荐`）→ e2e 红在"建议里应当有那条公开项目"，证明这条门
  验的是"建议来自真实命中"，不是列表有没有渲染。
- 读数：`apps/web/test/search-history.test.ts` 8 条纯函数；`e2e/search-suggest.spec.ts` 2 条
  （建议 + 历史）全绿；`/api/search/suggest?q=mvsj0rjc` 匿名返回 1 条公开项目。
- 仍欠：429 时界面只是不显示建议（结果页照常可用），没有"歇一秒"的可见提示；建议的点击率/
  命中质量没有真流量读数；跨设备历史需要账户体系层的决定，本 ADR 明确不做。
