# ADR-0070：限流闸的 IP 取可信链的右端，不取客户端写的最左端

- 状态：已接受（2026-10-30）
- 相关：ADR-0060（guest 自动签发需要身份之前的闸）、SECURITY.md「认证与授权」、§137、§159

## 背景

`apps/web/src/server/security/rateLimit.ts` 的 `clientIp()` 原来这样读转发头：

```ts
const xff = request.headers.get('x-forwarded-for');
if (xff) return xff.split(',')[0]!.trim();   // ← 最左端
return request.headers.get('x-real-ip');
```

`x-forwarded-for` 的写法是**追加**：每一跳把自己亲眼看到的对端补到最右边。所以最右那一段是
"离本应用最近的那个连接"，它左边的全部是上游说的、或者客户端自己写的。取 `[0]` 取的就是最后者。

两个事实叠起来，这道闸对任何会写头的客户端等于不存在：

1. `node_modules/next/dist/server/base-server.js:612`：
   `req.headers['x-forwarded-for'] ??= originalRequest?.socket?.remoteAddress`——
   **头缺席时**才拿 socket 地址填那一个格；头在场时原样透传，既不追加也不校验。
2. 桶键的形状是 `路由|身份|IP`（`rateKey`），IP 段来自上面那个函数。

于是 `curl -H 'x-forwarded-for: 192.0.2.'$RANDOM` 每请求换一个桶：

- 13 处 `ipWriteGate`（`projects/create` 20/h、`account/api-tokens` 10/h、`ai/run` 与 `blocks`
  与 `follow` 60/h、`marketplace/create` 20/h、`published/report` 20/h……）当场空转；
- 30 处 `rateKey(route, clientIp(req), user.id)` 的按 IP 那半也空转——按身份那半仍在，
  但 §137 的 guest 自动签发让"身份"每请求都是新用户（这正是 ADR-0060 加 IP 闸的原因）。

ADR-0060 想堵的是"绕开 cookie 的客户端免成本地建用户 + 项目 + 文档 + 任务行"。它挡住了
**不换 IP 的**客户端，没挡住**换 IP 的**——而后者连 cookie 都不用碰，一行头就够。

`guest-write-gate.integration.test.ts` 那三条用例全绿着。原因是它们都只写**一段**头，
在只有一段的链条里"取最左"与"取最右"是同一件事：见证的形状没有区分度，这是清单式见证的典型盲区。

## 选项

1. **保持现状，只在文档里写"要信反代"**。不成立：问题不是信不信反代，是读了链条的哪一头。
2. **改用 `x-real-ip` 为准**。nginx 的 `X-Real-IP $remote_addr` 是**覆盖写**的，比 XFF 更难伪造，
   但不是所有反代都设这一行；且直接暴露时它同样是客户端能写的字段。可以作为回落，不能作为主判据。
3. **取可信链的右端 + 可配跳数**（本决定）。链条右端是"最近的一跳看到的对端"；部署把
   `NEXUS_TRUSTED_PROXY_COUNT` 按真实拓扑写好（默认 1 = 一级会追加的反代，或 dev 下 Next 自己填的 socket），
   多级 CDN → LB → 本机时设 2、3。
4. **只信 CIDR 白名单里的跳**（从右往左走，遇到不在名单里的段就停）。比 3 严格，但本应用在处理器里
   **拿不到 socket 对端**（Next 只在头缺席时填），白名单无从校验起——先把 3 做对，这一档留给真要做的时候补。
5. **限流不再依赖 IP，改按 guest 令牌 / 设备指纹**。令牌是客户端自发的随机数，指纹是伪造的邀请；
   方向错。

## 决定

`clientIp()` 与新的 `gateIp()` 读链条的**右端**，具体三件事：

1. **归一化并丢弃读不出的段**：去空白、去 `[...]`、去 IPv4 的 `:端口`，八位组 >255 或字符集不对的
   当它不存在。`evil-1` 不再是一个身份。
2. **`gateIp()` 把"两行头都不在场"与"头在场却读不出地址"分开**：前者仍按 ADR-0060 的口径让路
   （标识不出的请求给一个共享桶，是拿一种故障换另一种故障；真实 HTTP 路上走不到这一格，
   Next 会把 socket 地址填进来）；后者归进 `INVALID_IP_BUCKET`（`invalid-xff`）一个桶照常限——
   写一行垃圾换不来免限流。审计与 `rateKey` 那些点继续用 `clientIp()`，
   垃圾头在它们那里是 `null`（`audit_events.has_ip` 因此不会把垃圾说成"有 IP"）。
3. **`NEXUS_TRUSTED_PROXY_COUNT`** 决定从右往左数第几段，默认 1；非整数、`<1`、`>8` 都退回 1
   ——**任何解析失败都不会退回"取最左端"**。链条比声明的跳数短就取到最左那一段（缺的跳只可能是
   客户端自己那一跳）。

限额一个都没改：`projects/create` 仍是 20/小时，`auth/register` 仍是 10/小时，
`auth/login` 仍是按邮箱 10 次/15 分钟。这一片改的是"闸按谁限"，不是"闸限多少"。

## 后果

**好了的地方**：一行头换一个新桶这条路断了；多级链条有了明确的配置口径；垃圾头从"每次一个新桶"
变成"全体共用一个桶"。

**仍然挡不住的地方（要紧，别读成已经解决了）**：

1. **直接暴露（前面没有会追加的反代）时，右端也仍然是客户端写的**。因为 Next 的 `??=` 只在头缺席时
   填 socket 地址，处理器里"客户端自带的头"与"Next 填的头"长得一模一样，分辨不出来。
   这一档只能靠部署补一个前置反代（并把 `NEXUS_TRUSTED_PROXY_COUNT` 设对）。
   部署文档 `docs/RUNTIME.md` / `docs/ENVIRONMENT.md` 要按这条写。
2. **内存驱动仍然每实例一套桶**，重启即失忆——多实例部署下这道闸的额度是"每实例 20"。
   换 Redis 有序集那一格照旧欠着（`hit()` 要变 async，33 处调用点 / 30 个文件）。
3. IP 是粗粒度身份：同一 NAT 后的人共用一个桶。所以这里取的是宽额度，"这个人"仍由按身份的闸管。
4. 取右端以后，**一个能控制真实上游 IP 的人**（比如同机另一个服务）仍能用那个地址换桶——
   那是"谁能写到链条右端"的部署问题，不是解析问题。

**见证**（逐字读数在 `docs/ROADMAP.md` 文末「§SEC 限流闸的 IP 取可信链的右端」一节）：

- `apps/web/test/client-ip.test.ts` 15 条（改实现**前**跑：11 failed / 4 passed——这四条正是
  "只有一段"与"没有头"那两种在旧读法下也能过的形状，这就是旧见证没有区分度的读数）。
- `apps/web/test/guest-write-gate.integration.test.ts` 6 条（真库真路由）：链条左端轮换 + 右端固定
  25 次 → 前 20 放行、后 5 个 429、`guest` 只多 20 个；垃圾头 25 次同样第 21 次起 429。
- **活体 HTTP**（`.scratch/s26-forwarded-live-probe.mjs`，打真 dev server，不经手搓 Request）：
  21 次"左端轮换 + 右端固定"→ 第 21 次 429；P1 单段（就是那只满桶）→ 429，证明这一行头
  确实原样走到处理器、没被 Next 用 socket 覆盖；P2 `满桶, 全新地址` → **404**，
  而**旧读法在这一站会 429**（它取的是左边那只满桶）。这一趟把"读源码"换成"观测"。
- `apps/web/test/rateLimit.test.ts` 那条旧断言从 `1.1.1.1` 改成 `2.2.2.2`——**这条断言原来就是在给
  漏洞作证**，它写的是"取第一段"并真的取到了第一段。
- 变异臂 6 条逐个点名（M1 取最左端 = 单元 8 红 + 集成 1 红；M2 垃圾头改豁免 = 单元 1 红 + 集成 1 红；
  M3 env 成装饰 = 1 红；M4 不回落 x-real-ip = 1 红；M5 去掉夹住 = 1 红；M6 垃圾段也当身份 = 3 红）。
  M3 那臂要说清限度：它只让"count 往左挪"那一格有牙，"非法值退回 1"那一格恒绿。
