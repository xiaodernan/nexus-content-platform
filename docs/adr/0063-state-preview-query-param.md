# ADR-0063：只读页的状态预览走服务端 `?state=`，而不是假装有运行时

## 背景

ADR-0062 把 §124 的状态层投影到预览与发布页时，披露了一条口径：`loading` / `error` / `success`
靠 `data-state` 属性兑现，但只读页没有运行时去设置这个属性，所以三种状态只在导出的代码里有语义。
作者在平台上无法验证自己写的 loading 样式到底长什么样——这等于状态层有一半是"写了但看不到"。

## 选项

1. **客户端模拟器**：在预览页挂一个客户端组件，用按钮切换 `data-state`。
   预览页现在是服务端渲染、不依赖 JS 的；为演示引入一个客户端岛，等于多一条与 SSR 并行的渲染路径。
2. **服务端查询参数**：`/preview/:id?state=loading`，链接式切换，服务端直接把 `data-state`
   写到节点上。零 JS、可收藏、可分享；与现有 SSR 投影共用一份 `stateStyleSheetFor`。
3. **把状态也画在画布上**：违反 ADR-0062 的边界——画布是编辑面，hover/状态外观会和选择、
   拖拽、手柄互相干扰。

## 决定

**选 2**，并配五条约束：

- **只列真能演示的三个状态**。`hover` / `active` / `focus` 是浏览器伪类，直接在元素上操作就生效，
  不需要参数；`disabled` 只对真实表单控件生效，而投影出来的节点是 `div`。界面上只给
  loading / error / success 三个链接，不摆一排点了没反应的按钮。
- **只有定义了该状态的节点才挂 `data-state`**。否则一个页面参数会让所有节点"看起来变了"，
  而作者从没为它们写过那个状态——这是假投影。没定义的节点一个字节不动。
- **状态栏只在页面确实有状态规则时出现**（`stateStyleSheetFor` 返回非空串）。没有状态的项目
  不该看到一个"无效控件"。
- **切状态不丢取景框**：链接把 `page` / `viewport` / `zoom` 原样带过去。看状态是查看，
  不该顺带把作者正在看的断点重置掉。
- **非法的 `state` 值退回基础态**，不 404：一条过期或被手改的链接仍然应该看到页面。

## 后果

- 发布页**不提供**这个控件：访客看的是作者的内容，不是状态模拟器。快照里的 hover 等伪类状态
  照常由指针/焦点触发（ADR-0062 part ④ 的访客页见证）。
- 这不是运行时：真正的 loading 需要作者自己的应用去设 `data-state`。预览页把它明说成
  "状态预览"，不声称节点此刻真的在加载。
- 见证：`e2e/studio.spec.ts` 的「§124 状态预览」——面板写入
  `data-[state=loading]:opacity-[0.4]` → 预览基础态 opacity 1 → `?state=loading` 后 CTA 0.4、
  Headline 仍 1 且没有 `data-state` → 切 error（未定义）回 1 → 回基础态且 `viewport=tablet` 仍在。
- 三条链接是服务端渲染的 `<a>`，键盘可达（§90）；当前项用底色标出，不依赖颜色单独传达状态
  （文案里同样写着当前预览的是哪个状态）。
