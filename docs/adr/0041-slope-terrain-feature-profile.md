# ADR-0041：坡地 = 每个地形特征自带剖面（profile），不做网格高度场

日期：2026-10-15 · 状态：已采纳 · 关联：§140（第四片 ADR-0034 / 第五片）

## 背景

§140 第四片落地了可走的圆台（mesa），当时欠账清单里写着"仍欠：真正的坡地/高度场"。
"坡地"有两种做法，必须选一条：

- **A. 网格高度场**：世界一块矩形区域采样成 N×N 的高度数组，行走/渲染都查表。
- **B. 特征剖面**：地形仍是作者画的几何特征（圆台），每个特征声明自己的剖面
  （mesa 硬边 / cone 线性坡），高度查询沿用 `terrainHeightAt` 的"特征遍历取最高"。

## 选项

- **A 网格高度场**
  - 优点：任意形状（山脊、盆地、多个峰）都表达得出来；渲染可直接位移三角网。
  - 缺点：
    1. 与 §16 相反——设计模型是唯一真值，网格是另一份需要与特征对齐的**采样数据**。
       作者在 2D 图上"画一个坡"到不了网格：要么从特征烘焙（烘焙之后真相仍在特征里，
       网格只是缓存），要么手刷（手刷就没有图上的语义可对账，undo/校验也没了对象）。
    2. 精度 = 格距：坡心不在格点上时高度就错，"`terrainHeightAt` 是相机与点击射线
       唯一读的那份查询"这条等式要重新证明。
    3. 第四片定下的逐特征纪律（`WORLD_PLATEAU_LIMIT` 上限、写入端校验、面板列表、
       图上的一个圆、undo 一次撤一个特征）在网格上全部失效，要重写一套。
- **B 特征剖面（选这条）**
  - 优点：
    1. 一切逐特征的纪律照旧：第五片只加了一个枚举值，没有第二套模型。
    2. cone 的高度是闭式解（`height * (1 - d/radius)`），单测三点钉住线性；相机贴地、
       点击射线、e2e 的 `data-walk-height` 全部走同一个 `terrainHeightAt`，等式不证自明。
    3. 老文档零迁移：缺省 = mesa，存盘形状逐字节不变。
  - 缺点：表达不了"两个峰夹一条谷"这类需要凹处的形状（重叠只有 max，没有减法）。
    按 §159 这条限度如实写进 ADR 与 ROADMAP，不假装覆盖。

## 决定

采纳 B。`WorldPlateau.profile?: 'mesa' | 'cone'`，缺省 mesa；cone 线性降到 0；
重叠取最高的语义对两种剖面统一；坏剖面拒收。不做网格高度场。

## 后果

- 要"谷"的时候是另一格：要么引入 `profile: 'valley'`（减法特征，参与 max 之前先减）——
  那要把 `terrainHeightAt` 从"取 max"改成"特征管线"，值得单独一片；要么等真有需求再说。
- 坡度上限（"太陡走不上去"）不在这一片：那是行走规则（`resolveWalkCollision` 的语义），
  不是地形形状。
- 2D 仍是虚线记号，不做等高线；等高线是给"读图"用的另一种投影，不是剖面的必要属性。
