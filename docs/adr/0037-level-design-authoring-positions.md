# ADR-0037：Level Design 这一格把布局从"每次现算的兜底"写成设计值，并且不许弄坏上一格的成绩

- 状态：已采纳（§52 第三片：Game Design → Combat Design → Level Design）
- 日期：2026-10-13
- 关联：§52、§53、§112、§113、§16、§54、§159、§160、ADR-0020（编排只读）、ADR-0035（产物的落地形状）、ADR-0036（第二格：吃上一格的草稿）

## 背景

前两格交出来的是「数值调进目标带了，但位置还不在这份设计里」的一份文档：玩家站在正中，
同类个体排在同心环上——那对数是 `play.ts` 每次编译**现算**的投影兜底，不是文档里的值。
加第三格时撞上三个此前没人回答过的问题：

1. **"关卡设计"在没有 provider 时能做什么**？能回答的只有确定性的那一半（把位置写成值、
   按写死的几何目标摆开），而 §159 禁的正是把这一半说成另一半。
2. **布局到底住在哪儿**？§16 说设计模型是唯一真值，而这一格之前的"位置"其实住在投影里——
   画布上看得见、文档里读不到。这种位置改不了、进不了版本历史、也不是作者写的。
3. **上一格的成果会不会被这一格弄坏**？位置会改变四种走法的读数（距离、能不能碰到目标），
   所以布局与数值会在**同一份报告**上打架。第二格刚立的五条战斗目标如果第三格能随便踩，
   那条链就不是"往前走"而是"来回摇摆"。

还有一条上一片留下的教训在原地等着：披露文字里手写的条数会漂移。这一片开工时界面上写的是
「五步作业」，而配方已经有七步——那句话是第二片时抄的，抄完就没人再对过。

## 选项

1. **让 Combat 那格顺手把位置也调了**。否：它的七条杠杆全是数值，而"站着不动也能赢"有
   **纯布局**的那一半（目标物压在出生点上时 idle 走法在第一帧就满足条件，
   把察觉半径调到天上去也救不回来）。`test/level.test.ts` 用同一份文档跑两遍把这条界线钉住：
   `tuneCombat` 用尽七条杠杆修不好，`designLevel` 一轮修好。
2. **只做几何报告，不改文档**（像 §53 那样读一遍就走）。否：那样布局仍然是投影算出来的，
   第 2 个问题一点没动，链子停在原地。
3. **把位置写成设计文档的组件属性**（走 §16 那套节点/组件，而不是游戏实体的数值）。否：
   §54 的游戏文档是一项目一份整份 JSON，实体本来就带 `stats`；为"位置"另开一条存储，
   等于让 Game Studio 有两个真值来源。
4. **本决定**：在 `packages/game-model` 加一层写死的几何规则（`LEVEL_RULES` / `LEVEL_LEVERS`），
   吃 combat 那份草稿，先把投影此刻排出来的位置**原样**写成文档里的 `x` / `y`，
   再按四条几何目标一轮一轮摆；保留条件同时护住上一格已达标的战斗目标；
   产物**还是草稿**，存在这一步自己的结论行。

## 决定

### 位置是设计值，来历要写在脸上

- `play.ts` 这一层先补上"文档里写的坐标"这个概念：`POSITION_STAT_KEYS`（`x` / `y`）、
  `hasAuthoredPosition`（两个键都是有限数才算作者摆过）、`authoredPosition`（读出来并钳进场地）。
  有作者值就用作者值，没有才退回同心环；玩家只在**没被写过位置**时钉在正中——
  写了就听作者的。
- 来历不许被抹掉：投影 HUD 把每个位置标成「文档写的」还是「兜底排的」，
  槽位与文案从 `PLAY_PROVENANCE_SLOTS` / `PLAY_PROVENANCE_LABELS` 派生，不是四个硬编码键。
  这句话有分量：`author-the-layout` 那一杠杆**一个像素都不挪**，它做的是把兜底值提升为作者值——
  提升之后画面上什么都不变，四种走法的报告必须**逐字节相同**。
  不点名来历，"我摆了关卡"就成了夸大。
- `LEVEL_GOAL_ORDER` 四条：先把布局写成设计值（`layout-authored`），再查
  别叠在一起（`not-piled`）、别把白拿的目标摆在出生点上（`spawn-clear`）、
  开局到最近敌人的距离在能反应的带里（`approach-band`）。
  `LEVEL_RULES` 是它们的阈值：间距下限 `2 * ACTOR_RADIUS`（正好是个体直径）、
  距离带 120–520、分开时多留 8 像素余量（正好卡在阈值上=下一次读数是抛硬币）、最多 12 轮。
  **这些数是我定的**，界面上与 notes 里都点名写死，不是需求里的验收标准。
- 四条目标各有一条杠杆（`LEVEL_LEVERS`），改的是坐标不是规则；越界钳回场内，
  钳回来还不达标就算这条杠杆用尽——这一版里没有地形、没有第二个房间，
  "这块场地挤不下"是真结论而不是待办。

### 保留条件护两样东西：本格的几何与上一格的战斗

- 与第二格同一条 `improved && broke.length === 0`，但 `broke` 的范围**扩到进入这一格时已达标的
  战斗目标**：候选改动只要让那几条少一条就撤回。打架时布局让路，因为"能不能玩"由数值格先把关。
- 撤回的轮次留在 `rounds`（`kept: false` + 原因），notes 逐条点名哪个杠杆破了哪条目标。
- `moves[].kind` 分 `author`（原样写成坐标）与 `shift`（真的挪了个体），界面上分开报数——
  合成一个"改了 N 处"就把"提升来历"和"动过位置"混成一件事。
- 机关（`trigger`）单独点名：它的位置原本可以由它引用的那个东西锚出来，
  给它写坐标等于把它从那个东西身上摘下来，不能混在"挪了个东西"里。
- 纯函数：`setStat` 写值、改过的实体 `updatedAt` 按传入的 `at` 统一盖回去，不读时钟、不碰库。

### 编排与接受入口

- `level` 是第七种步骤，`dependsOn: ['combat']`，`requires: 'game.write'`，产物 `level_layout`。
  `RUNNERS` 是 `Record<StepKind, Runner>`，漏一格是编译错误。
- **拿不到上游草稿就直接失败**（`throw`，这一步落 `failed`，`counts` 空、`notes` 空），
  不另编一份设计来"摆"。与第二格同一条：这一步没有输入就没有输出。
- 接受入口今天面对**三份**草稿（game 原始 / combat 调过数值 / level 摆过位置），
  `stepId` 缺省仍是"这份任务里最后一个留了草稿的步骤"，也就是链末那一份。
  `createOnly` 不变：一次作业三份草稿，项目只能有一份游戏设计。
- 面板上那句作业介绍里的**步数改成从 `READINESS_STEPS.length` 派生**，不再手抄。
  这不是美化措辞：手抄的那一句在第二片之后就已经是错账，而它恰好在"这一轮什么都不改"
  这句承诺旁边——数字错了，那句话的可信度也跟着掉。

## 怎么被钉住的

- 纯层 27 条（`packages/game-model/test/level.test.ts`）：表形状（每条目标都有杠杆、id 顺序）、
  每一处保留的挪动都能在读回来的文档里找到那两个数（`replayKept` 把改动叠回原稿逐键比）、
  撤回的轮一个坐标都不留、`author-the-layout` 之后四种走法的报告**逐字节相同**、
  与第二格的界线用**同一份文档**跑两遍、三种停止原因（`round-cap` / `no-lever-left` / `not-runnable`）
  各有真形状把它跑出来而不是我在测试里造报告对象。
- 13 臂行为性变异（逐臂红的用例名记在 `docs/TESTING.md` 2026-10-13 那一格）：保留条件的两半各删一次、
  只护布局 / 只护战斗、半套坐标当成摆过、机关的覆盖不算、已摆过的位置当成没摆过、距离读数不取负、
  留下负零、两点重合时不兜方向、`author` 偷偷挪一个像素、分开距离少留一档、让路距离少留一档，
  外加接线层 6 臂与只在真浏览器里量的那一臂。有**两臂最初是绿的**，根因不同但都归同一类洞：
  - **「让路距离少留一档」是分支不可达**：「压在出生点上」与「叠在一起」用的是同一个判据
    （间距小于 `minGapPixels`），而 `not-piled` 排在 `spawn-clear` 前面，正常情况下
    `separate-pairs` 已经把那件物品挪开，`clear-the-spawn` 的物品分支**根本轮不到执行**。
    补的底稿是 `stackedFour()`——它把那条分支走出来，那条臂才红得起来。
  - **「已摆过的位置当成没摆过」是读数等价**：`author` 那条杠杆写进文档的数取自投影**此刻**排的位置，
    而摆过的那个个体投影排出来的仍是它自己那一对数——覆盖一遍与跳过连交回的文档字节都一样，
    能区分两者的只剩改动清单。补的用例给一份混合底稿（四个还在同心环上、物品的位置由作者写在场地角上），
    钉住「清单里不许出现作者已经摆过的那个个体」，重跑该臂 → 红 1 条。
  这与 ADR-0036 记的 `C`/`W7` 是同一类洞：**分支存在不等于分支可达，读数相等不等于来源相同**。
- web 层：编排集成测多三条（守卫失败时这一步 `failed` 且话里点名"没拿到 combat 的草稿"、
  除了坐标与时间戳之外两份草稿**逐键相等**、跑不起来那份的达标条数按存进任务行的那份重算且
  0 轮 0 处改动）、接受集成测把三步都留草稿与 `available` 清单钉住。
  「只改坐标」那条是这一格独有的形状：与最初那份比看不见布局格动了什么，
  而这一格的限度写的正是"数值一个都不动"——分母必须用上一格那份。
- e2e `@smoke`：真浏览器里点 `level` 那一格，落库那一份带作者摆的位置；
  判别证据用这一片给得出的最细的刻度——level 与 combat 那两份**只差坐标**，
  所以"库里有坐标、combat 那份一个都没有"排除了"传错 `stepId` 也照样绿"。
  随后点 `game` 与 `combat` 各被拒一次且库逐字节不动（第二格那份位置更少，
  覆盖了就等于把刚摆好的布局抹掉）。截图 `agent-accept.png` / `agent-accept-refused.png`。

## 后果

- 好的一面：链子走到第三格，且这一格的输出**能证明它只做过它说的那两件事**
  （摘掉坐标与时间戳后与上游那份逐键相等）；布局第一次成为设计里的值，
  于是可改、可撤销、可进版本历史；上一格的成绩被这一格的保留条件护住，链子不会来回摇摆。
- 代价：几何阈值是我定的，定得对不对不由这一格回答。将来接 provider（#105）时
  这一层的价值不是被替换，而是继续当**裁判**：模型可以提议挪哪儿，
  但保留/撤回仍由这份常量表判。
- 代价：场地就这么大，挤不下是真结论。要做"更大的关卡"得先给模型加房间/地形，
  不是在这一格里放宽阈值。
- 代价：`author-the-layout` 写进文档的数**来自投影的同心环**，不是作者的手。
  这一步把来历照实说了，但那份布局的美术质量仍然为零——它是可编辑的起点，不是关卡设计成品。
- 未决：链的最后一格 Code（产物要能下载、**不得在主机执行**，§81）仍欠。
