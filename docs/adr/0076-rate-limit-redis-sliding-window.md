# ADR-0076：限流闸的窗口挪到 Redis——以及为什么"退回进程内"在这里是对的选择

状态：已采纳（2026-10-31）
关联：`docs/SECURITY.md`「认证与授权」、§64「Provider/后端可替换」、ADR-0028（实时总线的 Redis 驱动）、ADR-0060（身份之前的按 IP 兜底闸）、ADR-0070/0071（那一行头取哪一段）、ADR-0072（回收端点那 6 次/10 分钟）

## 背景

`apps/web/src/server/security/rateLimit.ts` 的顶部注释从 §64 那天起就写着两句话：

> 生产多实例时换成 Redis 驱动（ZRANGEBYSCORE + ZADD 的有序集滑动窗口），
> 保持本接口形状不变即可——和 storage 的 resolveStorage 一个套路。

形状那一句是这一片的前置：接口原来是**同步**的，而同步接口只有"进程内"这一种后端写得出来——
一次网络往返没有地方等它。所以提交 1（`3585dc8`）做的事只有把 `hit` / `reset` 改成异步
（44 个生产调用点补 `await`、测试里 15 个 `reset()` 补 `await`），判定逻辑一个字没动；
提交 2 才往那个缝里填驱动。分两个提交不是为了好看：这样"新增驱动"的 diff 里没有"顺便改了语义"。

多实例部署下的事实不是"没有闸"，是**闸的口径和文档说的不是同一句话**：
`10 次/15 分钟/邮箱` 变成"每台 10 次"，`6 次/10 分钟/审核员` 变成"每台 6 次"，
而没有任何一个读数会说这句变了。攻击者不需要绕过任何代码，只要把请求分摊到两台前端。

## 选项

1. **继续进程内，部署上限制"只有一台 web"**——不是技术方案，是把债写进运维文档。
2. **Redis 有序集滑动窗口**（本条）。
3. **Redis 固定窗口计数器**（`INCR` + `EXPIRE`）——最省事，但窗口边界处额度翻倍
   （59:59 打满 + 00:01 再打满）。这道闸挡的是暴力破解与"免成本写入口"，
   边界翻倍恰好是它要挡的那个形状。
4. **令牌桶**——突发性更贴用户体验，但现有语义（"窗口内 N 次"）、现有文档、现有限额表、
   现有测试全部要重写；而且 429 那句 `Retry-After` 现在的含义是"窗口里最早那条到期的时刻"，
   令牌桶给不出同话的读数。
5. **在 middleware / 边缘限流**——本仓库的调用点全在 API 路由与 `server/domain` 里
   （`getRateLimiter` 没有一个 middleware/edge 调用方，这也是 ioredis 能用在这里的前提之一），
   搬到 edge 等于换一层再重做，不属于这一片。

## 决定

选 2，并附三条硬约束——它们不是风格，每一条都是一类 bug 的形状。

**一、原子性放在服务端脚本里。** `ZREMRANGEBYSCORE` → `ZCARD` → `ZADD` 分成三条命令时，
两个并发请求能同时读到"窗口里还差一名"，于是双双挤进去，上限被**并发本身**突破。
Redis 单线程执行 Lua，脚本内部天然原子。

**二、时钟来自 `redis.call('TIME')`，不是客户端 `Date.now()`。** 一台权威。
多台机器时钟不齐时，各自的 `now` 会把同一个窗口在不同机器上切成不同的边界；
更糟的是快那台写进去的成员分数比慢那台的 `now` 还大，`ZREMRANGEBYSCORE` 删不掉它——
它会赖在窗口里冒充"未来的命中"。

**三、每条命中在有序集里的成员名必须唯一**（实例身份 + 本机单调序号）。
`ZADD` 对同名成员是"改分数"而不是"加一条"，所以成员名若取 `Date.now()`，
同一毫秒里的 N 条请求在集合里永远只占一格，`ZCARD` 恒等于 1，闸等于没装。
**这一条单实例的顺序语义测不出来**（顺序跑的用例每次都在不同毫秒），
所以它有自己的用例：一次突发 `limit+6` 条并发 → 放行的必须恰好 `limit` 条。

驱动选择只看 `NEXUS_REDIS_URL`（与实时总线同一个旋钮，不各设各的），默认仍是进程内：
不设它的部署逐行为照旧，这一片是 opt-in。门面 `rateLimit.ts` 只剩接口、桶键形状与选驱动；
两个驱动各在一个文件里，与 `realtime/` 的 `bus.ts` / `localBus.ts` / `redisBus.ts` 一一对应。

单例从模块变量挪到 `globalThis`（与 `bus.ts` 同一做法，但理由从这一片起才真正要紧）：
Next 按 route 各编译一份模块图，挂在模块变量上等于每台进程里有 N 份限流器。进程内驱动下无所谓
（桶键第一段就是路由名），Redis 驱动下每一份都自带一条连接与一份退回用的本机窗口——
"每实例独立限流"会退化成"每模块图独立限流"。

## 后果

**1）Redis 坏的时候闸不停摆——退回进程内，并且退回必须有名有姓。**
这是这一片与 ADR-0028 唯一取向相反的地方，而且是故意的：`realtime/bus.ts` 明确写着
"不在连接失败时悄悄退回进程内"，因为那条线路坏了的表现是**收不到推送**，退回来的
"看起来正常"比报错更难查。这里的闸退回之后**仍然在挡东西**（挡得住单机暴力破解，
挡不住跨实例分摊），业务照常跑；不停摆的价值大于"看得见地坏"。于是代价换个地方付：
退回一定要**说出来**——`nexus_rate_limit_driver_fallbacks_total`（分 `reason`）、
一行限流日志、`fallbackCount` 读数，三个都是同一句话的形式。不吭声的退回等于把
"多实例共享计数"悄悄改成"看运气"。

**2）退回的方向是"更严"，不是"更松"。** `commandTimeout: 250ms` 到期的那条命令可能已经在
服务端执行完了，只是回执没赶上——于是它在 Redis 里记了一次、又在进程内记了一次。
两边各多算一点，配额只会更早用完，不会白送。**限流闸宁可往这个方向错**。

**3）`enableOfflineQueue: false` 意味着启动窗口里有几笔走本机窗口。** 连接就绪之前发出去的
命令当场被拒（不是排队——排队会把内存无上限堆起来，且重连后把积压的判定突然放出去），
那几笔由进程内那一份接管。退化是**有界的**：每台最多多放 `limit` 笔，不是免限流。
这一格不靠复盘发现：驱动暴露 `ready: Promise<boolean>`（永不 reject），测试与演练用它
代替"多打几次直到不红"那种把建连接竞态当成断言的写法；`hit` 从来不等它。

**4）Redis 的依赖等级变了。** 今天它是"实时通道的加速器"（坏了只降级，权威在库里）；
从这一片起它同时是"安全组件的共享状态"（坏了要退回）。所以后果 1 里那套退回不是
可选实现，是这一片成立的前提。

**5）`reset()` 不带参数 = 清整个前缀，跨实例一起归零。** 今天生产路径上没有任何调用方
（`reset` 的调用点全在测试里），所以这一格没有主人比有主人危险。测试**必须**用自己的
`keyPrefix` 换到独立命名空间：同一台开发 Redis 上还挂着另一条会话正在跑的 e2e，
把它们那 20 次/小时的额度抹掉，会让那一轮的"闸挡住了"变成"闸没挡"——
**读数看着一样，原因完全不同**。清前缀用 `SCAN`+`UNLINK` 不用 `KEYS`：后者在大库上是
一次 O(N) 阻塞，而这台 Redis 是共用的。`reset()` 还无条件先清本机那一份，
不管 Redis 那一趟成没成——旧宕机期间攒下的窗口不清，恢复后再抖一次就会挡人。

**6）每请求多一次往返**（本机 Redis，演练实测一次判定 1ms 量级），换来的是限额那句话
在多实例下重新成立。

**7）键空间自己收尾，而且这件事比看上去容易写错。** 每个 (路由, 身份, IP) 一个有序集，
`PEXPIRE` = 窗口长度。`PEXPIRE` 必须排在 `ZADD` 之后：对一个还不存在的键它返回 0、
什么都不做、也不报错。第一版把它排在 `ZCARD` 之前，于是**第一次命中建不出 TTL**——
而"只来过一次"的组合恰恰是绝大多数桶，每个都留下一只永久的有序集，键空间随流量单调涨。
这一格是 `键的寿命` 用例在 2026-10-31 首跑抓出来的（见下面"验证"的臂 A8），不是设计时想到的。

## 验证

- **同形用例**（`apps/web/test/rate-limit.redis.integration.test.ts` 的 parity 一组）：同一串
  请求分别打到两个驱动，每格 `allowed / count` 必须**逐格相同**。三档限额（1 / 3 / 5）各跑一遍。
  **`retryAfterMs` 这一栏本条原来写的是"在 50ms 容差内"，那是仪器写错了，下一片（ADR-0077）改的**：
  倒计时量的是"这一趟驱动自己走了多久"，两边的时钟本来两套（进程内用主机 `Date.now()`，
  Redis 用服务端 `TIME`），同一格的差值里混着调度间隙与一次往返。本文件落地那天单跑一次读到
  最大 3ms 就把它当成了容差上限；2026-10-31 连跑三次红在 55 / 62 / 64ms，而同一条用例里
  `allowed / count` 一格没差——**红得没有道理的门，下一次真分歧也不会绿**。现在钉的是与漂移无关的
  三句：不许一边说"不用等"一边说"还得等"、说"还得等"的不许超过整个窗口、两边的差不超过
  一个窗口 + 1s（真分歧一次差出秒级，噪声是几十毫秒级）。行为版本另有一条：真的等完再打一次。
- 跨实例：两个 limiter、两份独立连接、同一个桶 → 放行总数 = `limit`，不是 `2×limit`；
  **并且配一条对照**——同样两个对象换成进程内驱动就是 `2×limit`。少了对照，前一条在单实例下也能绿。
- 同毫秒突发：一次 `Promise.all` 连发 10 条、限额 4 → 恰好放行 4 条，Redis 里 4 条成员。
- 被挡下的那一次不进窗口：撞上限之后再打，`ZCARD` 仍是 1；等到窗口滑过仍能放行。
- 坏回执：`decodeDecision` 认不出的形状**不许读成放行**，走退回并记账。这一条没有常驻的假服务器，
  用臂 A9（把 Lua 的 `return { 0, count, retry }` 换成 `return 'nope'`）证明它有牙。
- 连不上：指向没人监听的 56399 → `ready=false`、每请求仍拿到决策、不抛、退回计数在涨、
  限额仍生效；同一趟里指标 `..._driver_fallbacks_total{reason="command-failed"}` 涨 4（运行时凭证）。
- `reset` 的爆炸半径：只清自己前缀；对照前缀**故意不是自己的子串**，扫到别人就红。
- 键的寿命：单次命中之后 `PTTL ∈ (0, windowMs]`，等过窗口键自己消失。
- **两个真实操作系统进程**的演练（`npm run ratelimit:two-process`，`scripts/rate-limit-two-process.mts`）：
  上面那两个 limiter 共享的是同一个进程与同一份模块图；这里 12 个进程各走 `getRateLimiter()`，
  进程之间唯一的通道是那台 Redis，判据读的是父进程自己 `ZRANGE` 出来的集合而不是孩子进程的自述。
  2026-10-31 那一跑 11 条判据全绿，其中：
  `SHARED_WINDOW_CAPPED` = `true / true / true / false`（四个进程各一次），
  `MEMORY_COUNTS_SEPARATELY` = `true / true / true / true`（对照），
  `CROSS_PROCESS_ATOMIC_BURST` = 两进程同时各 5 条并发，合计放行 4 条、集合里 4 条，
  `WINDOW_IN_REDIS_HAS_LIMIT_MEMBERS` 的读数 `25168:…:1 | 30596:…:1 | 32940:…:1`（三个不同 pid），
  `REDIS_DOWN_STILL_GATES` = 放放放挡挡、5 次退回、退出码 0。

臂表（每条都是改一处源码、跑、立刻改回来；`grep -c "MUT "` 归零才算收尾）：

| 臂 | 改了什么 | 结果 |
| --- | --- | --- |
| A4 | 成员名换成 `${origin}:${Date.now()}`（撞车） | 突发那格红：10 条**全放行**（应为 4）——顺序用例一条条都绿，正是"这条约束单实例测不出来"的形状 |
| A5 | 演练里 redis 段那四个进程指向 56399 | 5 条判据红、脚本非零退出（`SHARED_WINDOW_CAPPED` / `CHILDREN_USE_REDIS_DRIVER` / `BLOCKED_DECISION_CARRIES_RETRY_AFTER` / `WINDOW_IN_REDIS_HAS_LIMIT_MEMBERS` / `NO_FALLBACK_ON_REDIS_PHASE`），而 `REDIS_DOWN_STILL_GATES` 照样绿——判据读的是线路，不是磁盘上那份报告 |
| A6 | Lua 的 `count < limit` 改成 `<=`（差一名） | 6 条红，parity 表直接把分歧读出来：`[[true,1],[false,1],…]` vs `[[true,1],[true,2],…]` |
| A8 | `PEXPIRE` 挪回 `ZCARD` 之后、`ZADD` 之前 | 只有 `键的寿命` 一条红（`PTTL=-1`）——没有这一格，键空间泄漏没人看得见 |
| A9 | Lua 的拒绝回执换成 `return 'nope'` | 7 条红，含"正常路径下 `fallbackCount` 一直是 0"那格——陌生回执这条分支因此不是惰性臂 |

没跑的臂，点名：
- **"把脚本拆成两条命令"（原子性那一格的反证）**：它要求重写整段 Lua 而不是一行改动，
  这一片没跑。常驻的牙是同毫秒突发那条（A4 已经证明它真的在数并发路径上的成员）。
- **两台机器时钟不齐**：本机演练的 12 个进程共享一个系统时钟，这一格今天没有门。
  约束仍然写在决定二里，但它目前是**推理**，不是读数。
- **`SCAN MATCH *` 越出前缀**：不跑（会把并行会话那 20 次/小时的窗口真删掉）。
  这一格靠常驻用例：对照前缀不是自己的子串，扫过去就红。

## 仍欠

1. Redis 侧的键基数没有上界保护。进程内那版有指标序列折叠（`nexus_metric_cardinality_overflow_total`），
   这里没有对应物：活跃 (路由,身份,IP) 组合的数由真实流量决定，靠 TTL 收尾而不是靠上限。
   —— **这一格已还**（ADR-0081，2026-11-03）：桶键名册 + `maxBucketKeys`（默认 50 000），
   到上界**不再新建桶键**，那条请求交给进程内窗口判并记 `{reason="over-cap"}`。
   "靠 TTL 收尾"从今天起是两条腿而不是一条：单只桶的寿命仍是 `PEXPIRE`，条数另有名册钉住。
2. "这台实例现在用的是哪个驱动"没有界面位。`RealtimeBus` 有 `stats()`，`RateLimiter` 没有——
   加它要动接口，两个驱动都得实现，留给下一个真的要看这个数的人。今天的答案只有启动那一行日志
   （`[rateLimit] 驱动=…`）与 `nexus_rate_limit_driver_fallbacks_total` 有没有数。
3. 多库 / 集群部署下 `SCAN` 的 `MATCH` 只覆盖所连的那个 db。
4. 演练脚本不是常驻门（和 `realtime:two-process` 一样是手跑的）。回收路径的跨实例演练也还欠着。
5. 退回用的 `MemoryRateLimiter` 与 Redis 那一份是两套数：退回期间一台机器的额度是**它自己看到的
   次数**。这一点由 `FALLBACK_SCOPE_IS_PER_PROCESS` 那条判据写在演练输出里，不需要界面，
   但也没有任何东西能在运行时提醒运维"现在正在退回"——只有那个 counter 涨。
