# ADR-0276：公开「全站账本」入口 —— 汇绿到 `/insight`（/admin/pulse 并轨退役）（§九）

## 状态
**取代 v880 的初版方案（本文件为定稿）。2026-11-17 · v883 并轨完成。**

## 背景

用户长期指令（长期重复）：

> 开发一个管理员功能（密码输入 123 就能进，所有用户都知道密码也都能进管理员页面），用来检测、分析、查看、观察所有用户的行为。管理员页面里要能监控所有用户的统计数据、做分析和趋势预测，并根据这些数据给出下一步应该采取的深度优化措施。

v880 我开发了 `/admin/pulse` 满足它 —— 事后核对发现：

**`/insight`（公开口令 123 · 服务器现聚合 · 全站行为账本）早已完成这件事，而且字段更全、设计更成熟：**
- 总账、近 30 天日序列 + 线性外推（R² 实标）、行为信号（发布转化、guest 占比、互动率、爬虫占比、额度消耗率）、
  LLM 成本与缓存命中（30 天账本口径，与 /admin/savings 同源）、
  **深度优化建议（确定性规则，带阈值与证据，非模型猜测）**、最受欢迎发布作品、NN/g 公开研究基准、
  ⑧《大模型解读》现场喂给 gpt-6.1-terra 的实测解读（guide §⑪ 已记录、§PROVED 序列已覆盖其 E2E）。

两件事并排跑会造成：两份口径、两个 123 入口、两个要维护的聚合查询 —— 这正是"汇到一个主分支"要消灭的分叉。

## 决定

1. **公开口径（123）的权威入口是 `/insight`**（页面已存在、guide 已登记、PROVED 序列已覆盖实测）。
2. **`/admin/pulse` 按并轨退役**：删除 page、两条 route（unlock/narrate）、`pulse-gate.ts`、`pulse.ts`、
   两个测试文件；限流表移除 `pulse/*`；`METRICS` 移除 `nexus_pulse_narrate_*`。
3. **保留的不是页面，是诊断链**（v880→v881 的两处真 bug 修复留在共享代码里）：
   - `nexus_bible_ask_total/latency_ms` 的 `outcome` 枚举补上 `answer-unverified`（此前任何一条
     verdict=fail 的问典响应会让 `resolveSeriesKey` **直接 throw**，把路由打挂）——真实崩溃修复，不受页面去留影响。
   - 从 v879/v880 的真机实测里沉淀：「raw sql 裸插 JS Date」会被 PG 以
     `Wed Nov 04 2026 19:24:52 GMT+0800…` 拒绝、整页走错误分支——教训如下：任何 Date 进 raw sql，
     一律走 drizzle 列映射器（`gte/and/isNull`），不要 `${date}`。/insight 的写法即如此。
4. **不维护两套实现**；未来 §九 的任何增强一律落在 /insight（入口、signals、rules、narrate 均在此）。

## 后果

- 公开口径页面只有一份、口径一致、零漂移； guide ⑪ 无需修改（/insight 早已是它写的那个入口）。
- /insight 的聚合读取继续复用 `server/domain/insight.ts`；_rate limit_ 与 503-回真纪律不变。
- 承认 v880/v881 那一段是"新源实现先落地、再并轨收敛"的教训：**开工建页之前先全站 grep 一遍
  （或读 `app/` 目录一次）能挡掉这类重复造轮。** 证据链里 v880/v881 的实测仍真实有效
  （pulse 当时能渲染、narrate 拿 200 的对话、Date-bug 的修复），记录保留，结论并轨。
