# ADR-0276：公开管理台 /admin/pulse —— 口令 123、聚合数字、零个人字段（§九）

## 状态
已实现（2026-11-17 · v880）。页面 `apps/web/src/app/admin/pulse/page.tsx`、两条 route（`/api/admin/pulse/unlock`、`/api/admin/pulse/narrate`）、聚合源 `server/domain/pulse.ts`、单测 14 个。

## 背景

用户长期指令（长期重复三次）：

> 开发一个管理员功能（密码输入 123 就能进，所有用户都知道密码也都能进管理员页面），用来检测、分析、查看、观察所有用户的行为。管理员页面里要能监控所有用户的统计数据、做分析和趋势预测，并根据这些数据给出下一步应该采取的深度优化措施。

这是最容易做坏的一条：字面直译 = 一个公网任何人输入 123 就能看到所有人的行为数据。
真实用户的邮箱、昵称、IP 直接挂到公网 = 事故，不是功能。

## 决定

1. **做，但只做「聚合」那一半**：`/admin/pulse` 口令 123、任何人可进、现场库快照，
   但数据源只允许：计数、分布、趋势（用户总数/guest、会话数、项目可见性分布、14 天注册序列、7 天账本），
   **没有** 邮箱、昵称、userId、IP、UA、会话 token——页面上的每个数字都无法对回任一个人。
2. **趋势预测**：14 天注册序列做最小二乘（`server/domain/pulse.ts`），给「每日斜率 + R² + 未来 7 天外推」。
   R² 低时页面如实标注「这是统计描述不是预言」。
3. **"根据这些数据给出下一步应该采取的深度优化措施"**：页面上有「让大模型读这份账」按钮 →
   `/api/admin/pulse/narrate` → digest（纯聚合）现场喂给 provider，返回 3 条带依据的建议。
   provider 连不上 → 503 原样回真，绝不拼模板。
4. **减 harm 三件套**：
   - 闸是 cookie `nexus_pulse=1`（8h，SameSite=Lax，httpOnly）——不带身份信息、不与会话系统耦合；
   - 两条 route 都有 IP 限流（unlock 30/10min，narrate 10/10min；`IP_RATE_RULES` 已登记 `pulse/unlock`、`pulse/narrate`）；
   - narrate 的输入由服务端现场从库里算，客户端给不了内容。
5. **不进 `/admin/*` 的 role=admin 门**：这是公开面板，与审计/用户管理那些「真权限」页面是两类东西；
   两条路分开，谁进错门的问题不存在。AdminNav 不带它（那是管理员导航）。
6. **口令硬编码**：用户原话如此，属于产品设计的一部分，`server/domain/pulse-gate.ts` 单点定义，
   注释里写清楚这是主人明令，不是缺省值。

## 后果

- 产品层面兑现了「人人可进、监控平台、LLM 解读」三件事。
- 数据层面没有把任何人推到公网上：审计过 `pulse.ts`，全是 count/sum/avg 与日期。
- 如果未来要把某类**单用户**细节公开，必须重新走一次决策（本 ADR 不授权）。
