# ADR-0038：Code 这一格把设计投影成拿得走的产物，代价是承认它是"转写"，并给这句谎配一条真浏览器见证

- 状态：已采纳（§52 第四片：Game Design → Combat Design → Level Design → **Code**）
- 日期：2026-10-14
- 关联：§52、§16、§54、§81、§159、§160、ADR-0035（产物的落地形状）、ADR-0036（第二格）、ADR-0037（第三格）、`docs/SECURITY.md`

## 背景

前三格交回来的是一份「数值进了目标带、位置也写成设计值」的文档。这一格要的是**拿得走的东西**：
作者点一下就能在自己机器上跑起来的那一份。三条约束在这里同时收紧：

1. **§16 说设计模型是唯一真值**。产物一旦能独立运行，它就成了第二个说话的地方：
   冷却写两遍、事件上限写两遍、计划序列化两遍，迟早有一处与文档分叉，而用户看到的是产物。
2. **§81 说生成代码不得在主机执行**。所以"证明产物跑得对"不能靠 `eval`、`new Function`、
   也不能起子进程跑产物——能用的只有浏览器沙箱那一条路。
3. **§159 禁止把没做的事说成做了**。这一格没有 AI、没有打包、没有手柄、没有关卡布局，
   界面上就不许出现"一键发布""与平台完全一致"这类话。

## 选项

1. **产物直接引用平台的引擎**（把 `sim.ts` 编译成一份 JS 打进产物）。否：
   那要求把 TS 编译链塞进生成路径，并且产物会连带 `import` 一整个包的依赖图；
   §81 允许的是"产物自包含地在沙箱里跑"，不是"产物在玩家机器上重新解析平台源码"。
2. **产物自己重写一套规则**。否：那是最直白的第二份真值（§16），而且重写的那一套没人保证算术相同。
3. **转写 + 数字由同一处供给 + 浏览器里量一致性**（选定）：
   `engine.js` 是 `sim.ts` 的逐行转写，规则数字与那句"没有玩家跑不起来"的拒绝
   **从 `sim.ts` 的导出插进模板**（为此把 `MAX_FRAME_SECONDS` / `EVENT_CAP` / `SIM_NO_PLAYER_OUTCOME`
   从 `step` 的字面量里提出来导出——留在原地就等于允许模板重打一遍）；
   而"转写会不会分叉"这句话由一条真浏览器见证来量，不由注释来保证。

## 决定

1. **一条投影链**。产物吃的是 `compileGame(document)` 排出来的那份 `GamePlan`，与 `GamePlay.tsx`
   今天吃的是同一个对象。`plan.json` 与 `plan.js` 必须是**同一次 `JSON.stringify` 的结果**——
   两处各写一遍就是两份计划，会出现"下载的那份是旧的、页面跑的是新的"。
2. **数字只从 `sim.ts` 的导出插**：`contactCooldown` / `playerAttackCooldown` / `maxFrameSeconds` /
   `eventCap` 与那句拒绝，全部插值，模板里不许出现对应字面量。
3. **产物只在浏览器里执行（§81）**。生成侧只有字符串拼接：不 `eval`、不起子进程、不读写文件、不联网。
   产物自带 CSP：`default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self';
   connect-src 'none'; frame-src 'none'; object-src 'none'`——一份下载的关卡不该在玩家机器上打洞。
4. **限度随产物一起交出去**。`CODEGEN_LIMITS` 是导出常量，README、界面、ZIP 说明都念同一份；
   其中第一句就是"产物里的引擎是 `sim.ts` 的**转写**"。界面上只报成功不报这四句，就算撒谎（§159）。
5. **出口是只读的**。`GET /api/projects/<id>/game/code` 从库里那份设计现算，不写库、不落盘：
   设计改一个数重新生成就是新的字节，所以没有"保存产物"，也没有"覆盖你上一份"要回答。
   归属先判（不是你的项目回 404，不是 403），响应体有上限，超了回 413 并报出字节数。
6. **跑不起来的设计也全量生成**。缺玩家不是"什么都不产出"，而是产出七份文件 + 打开就是失败态，
   README 里点名 `plan.blockers`。不为了"看起来能玩"补一个玩家。
7. **界面上那颗按钮跟着库走，不跟着屏走**。这一格的输入是库里那份设计（决定 5），所以屏上还欠着一次写
   （`dirty` / `saving`）时它必须点不动，并把原因写在旁边——按钮的可用性由 `gameStore` 的 `saveState` 派生，
   不是界面自己再判断一遍"有没有设计"。

## 后果

- **好消息：这条见证真的抓到了东西**。`scripts/game-code-parity.mts` 第一次跑就报出
  产物里所有敌人开局就是"死的"——`initialState` 用了 `cloneActors(plan.enemies)`，
  而计划里根本没有 `active` / `readyAt` 这两个字段（`sim.ts` 的初始态是自己点活的）。
  表现是：敌人不追、不打、物品捡不起来，页面摘要却照样显示"进行中"。
  那 17 条比对常量与键名的静态闸**全绿**，缺陷照跑。修法是给转写补一个与 `sim.ts` 的 `actor()`
  同形的 `startActors`，并在 `codegen.test.ts` 里留下一道读结构的闸 + 它的反向控制。
  这件事的结论写进纪律：**"转写等价"这类主张只能由把产物跑起来的那条见证来结账**。
- **第二个缺陷是 e2e 抓的，跟转写无关**：这一格读的是**库里**那份设计，而界面上一有改动就先把
  11 个实体画出来、PUT 还在飞。第一版那颗按钮在这种情况下照样能点，于是"刚建完骨架就生成"会收到
  一句「这份项目还没有游戏设计」——对着屏上明明存在的设计撒谎（§159）。现在库里那份没跟上屏上这份
  （`saveState` 为 `dirty` / `saving`）时按钮点不动，并且界面上写着为什么；写完了它自己松开。
  这一格只在真浏览器里量得着：把 `disabled={busy || behindLibrary}` 改回 `disabled={busy}`，
  e2e 红在 `expect(locator).toBeDisabled()` / `Received: enabled`，还原后绿。
- **代价：多了一条需要浏览器与 loopback 端口的见证**。它不进 vitest（vitest 里跑产物就是主机执行，
  §81 直接违），所以记在 `npm run parity:game-code`，读数写进 `docs/TESTING.md`。
- **界面能说的比想说的少**：不说"这就是平台跑的那一套"，说"是它的转写，数字由同一处供给"；
  不说"打包下载"，因为 ZIP 那一格还没接，现在是一个文件一个文件下。
- 编排链上的 `code` 那一步仍然欠着：这一格先有了出口（端点 + 界面），
  下一步才谈"在作业里点它"（产物照 ADR-0035 停在草稿层，不写库）。
