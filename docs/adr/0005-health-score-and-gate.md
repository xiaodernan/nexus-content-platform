# 0005 — 健康度打分：一份算法两处显示，没测的不是绿勾

状态：已采纳（2026-09-23，任务 #23，§178/§179）

## 背景

§178 要 Studio 里持续显示七行项目健康（Build · Tests · Accessibility · Performance · Visual QA · AI QA · Security），
§179 要 Publish 前跑 Quality Gate，不达标就挡。此前只有一条三检查的 `runPublishGate`，
没有分数、没有实时读数，也没有"哪些检查根本没跑"的表达位置。

麻烦的地方不是算不出来，而是**怎么算才算诚实**（§159）：
七行里有两行（Tests、AI QA）在本地没有任何可算信号，性能行也拿不到真实 LCP/CLS——
最省事的写法是给它们填 100，界面立刻"全绿"，而那正是这两条需求存在的理由被反着实现。

## 选项

1. **全部打分，缺数据填 100**：UI 好看，等于假绿。排除。
2. **只列发现，不给分**：诚实，但 §178 要的就是"一眼看出这一项现在几分"，
   而且没有分数线就没法定义"挡发布"。
3. **打分 + 第三种状态**：有信号的行按发现扣分并比阈值；没信号的行 `score = null`、
   `state = not-run`、`gating = false`，UI 显示"未评估"。

分数放在哪里算，也是同一个问题的两半：

- A. 服务端算，客户端只在发布失败后显示回传结果：数字是"事后残骸"，改一下要重新发布才知道。
- B. `analyzeHealth()` 放 `@nexus/design-model`，Studio 实时调、`runPublishGate()` 也调它：
  一处算法，两端同一份数（§16 的"唯一真值"精神）。

## 决定

选 **3 + B**。

- 扣分：`error 25 / warning 6 / info 1`，`100 - Σ`，下限 0。
- 阈值集中在 `HEALTH_THRESHOLDS`：Accessibility 80 · Performance 70 · Visual QA 60；
  Build 与 Security 的 `threshold = null`，语义是"有一条 error 就挡"，不是"分数线很低"。
- 检查规则复用 `validateDocument` + `lintDesign`，只补设计模型能静态算的部分
  （节点数、树深、位图字节、缺尺寸位图、动效数、越出画布、零尺寸、明文凭据、危险代码、http 外链）。
  不重造一套规则，是为了避免"Studio 说不达标、服务器说达标"这种双真相。
- 单行最多带 40 条发现（`MAX_FINDINGS`），其余计进 `omitted` 并在 UI 写明"另有 N 条（计分已计入）"：
  截的是报文显示，不是问题本身。
- 跨端报文过 zod（`ProjectHealthReportSchema`），客户端解析失败就当错误报出来，
  不拿一份读不懂的清单冒充门禁结论。

两个刻意的口子：

- **门禁只挡往外公开的方向**：`visibility = 'private'` 放行。切成私有是下架，
  挡住它等于让作者收不回一份坏页面；此时报告仍然带出全部失败项，面板上写明为什么放行。
- **测不出来就不报**：`measureContrast()` 任何一边算不出（渐变、图片填充、坏 token、
  最底层半透明且身后无依据）返回 `null` → 不产生发现。宁可漏报也不编一个比值。

## 后果

正面：
- Studio 与发布门禁共用一份算法，数字不可能对不上；"未评估"成了界面上一等公民，
  读者能看到哪里还没被检查过，而不是被一句"通过"糊过去。
- 阈值集中，改线只需要一处，且必须同时改测试。

代价与已经付掉的账：
- 阈值一旦生效，**自己的设计系统就得真的达标**。80 分线立起来之后，内置起手页与
  editorial / cinematic / cyber / warm 四套概念语言里多处真实不达标（白字压 `#7c5cff` 4.35:1、
  warm 方向奶油字压亮橙 3.35:1、cyber 的 light 模式深底配深字 1.08:1）全部暴露。
  按 WCAG 重算色板修数据，而不是下调阈值——`nodes.ts` / `concepts.ts` 的默认值因此变了，
  codegen / render 断言里的旧色值同步更新。
- 分数会被"同一类问题成片出现"拖垮（45 条 warning 直接归零），所以 UI 必须同时给出
  发现明细与 omitted 计数，否则分数就成了没法行动的惩罚。
- Performance 行是静态预算，不是真实性能；`basis` 里明写了这一点。要真数字得接 Lighthouse/浏览器实测，
  那是后续项，不是现在能给的分。
- Tests / AI QA 两行在接入真实信号前会一直是"未评估"。这是设计，不是待补的空位。
