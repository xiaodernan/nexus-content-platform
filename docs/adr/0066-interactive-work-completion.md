# ADR-0066：互动作品的 completion——终点判定在发布快照，走通证据在标签页

## 背景

§167/§168 给互动作品（非游戏）补上"多少人走通过"这一格。游戏的 completion（ADR-0054）由
可玩页的结局段触发；设计稿没有"结局段"这个概念，判定只能从模型推：一份文档里有
`click → navigate` 的交互，且某一页没有任何有效下一跳，那一页才是"终点"。

三个容易说谎的地方：

1. **终点由谁说了算**：客户端知道自己在哪一页，但客户端说的话不能当判定依据——
   伪造的 `pageId` 会把"有人打开了首页"记成"有人走通了"。
2. **"直接打开终点页"算不算走通**：把终点链接发给别人，对方点开——这一次没有走，
   只是到了。若只看"到达过终点页"，链接转发会被记成完成。
3. **与游戏通关同表还是分表**：两个事件粒度相同（人 × 版本一次），但判据、触发面、
   界面口径都不同。

## 选项

1. **客户端上报"我走通了"，服务端照记**：最省事，但计数器信了最不该信的一方。
2. **客户端只报 `path + pageId`，服务端按发布快照判**：`isTerminalInteractivePage` 在
   服务端重算"这一版有可走通的点击流程、且到达的页没有下一跳"。客户端能选的只有
   "报哪一个真实的页"。
3. **服务端跟踪每一步点击**：每翻一页都上报，服务端重放路径。判定最严，但一个
   两页的作品要造一张访问序列表，而"有没有从入口点过来"用页面本地的一个标记就能答。

## 决定

选 **2**，外加一个**标签页内的走通标记**：

- **判定在模型层、快照上**（`packages/design-model/src/interactions.ts`）：只有
  `click + navigate` 且目标真的是本文档另一页才算下一跳；悬浮、弹窗、自指、断链都不算。
  `hasClickNavigation` 为假的文档没有终点——静态作品连 400 都省不出错处地，
  `published_projects.interactive` 在发布那一刻把同一判定钉进库（迁移 `0044` 回填历史行）。
- **走通的证据是标签页里的一个 sessionStorage 标记**：热点点击时打标，终点页读到标记才上报。
  标记不跨标签页 ⇒ 直接打开终点页的访客显示"不算走通"，一行都不写；
  不进 localStorage ⇒ 关掉重开算新的一次尝试，服务端唯一索引保证仍只记一个人。
- **分表**（`work_completions`）：与 `game_completions` 同款纪律（唯一索引按
  `(publication_id, visitor_key)`、爬虫另计、只有作者自己走通要明说），但两格各说各的，
  分析页互不抄数。

## 后果

- **只认 `click + navigate`**：悬停、弹窗、状态切换在公开页上今天做不正，也铺成按钮
  （§159）——页面上有一句说明把它们如实豁免。
- **"走通"不证明"看懂了"**：一个人点对了一次按钮就算走通；它回答的是"这条点击流
  真的走得通、真的有人走"，不回答内容质量。
- **e2e 抓到过一次真 bug**：横幅的 `not-walked` 状态写进了文案与类型，effect 却漏了
  `setRecord`——直达终点页永远停在"checking"。集成层测不到它（那是纯客户端的状态机），
  `e2e/interactive-work.spec.ts` 的直达断言红过一次才补上。变异验证：把这一行拆掉，
  e2e 精确红在同一条断言上；恢复后绿。
