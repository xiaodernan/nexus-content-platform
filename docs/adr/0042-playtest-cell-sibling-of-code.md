# ADR-0042：试玩那一格进链——它与 code 是**兄弟**而不是前后两格，因为投影不读试玩报告

- 状态：已采纳（§52 链接上 §53 的四种走法，配方从八步变九步）
- 日期：2026-10-16
- 关联：§52、§53、§16、§25、§112、§113、§159、§160、§163、ADR-0039（code 那格的同一形状）、ADR-0040（种子既是入参也是读数）

## 背景

ADR-0039 落地时"还欠"那一节写着：把"试玩四种走法有几种通关"也接成链上的一格是下一步的事。
这一片就是那一格。但接法上有一个**新**决定，不是 ADR-0039 的复制：这一格挂在链上的**哪个位置**。

链当时的形状：

```
context / seo-audit / qa-audit → report      （三份检查与汇总）
game → combat → level → code                 （三份草稿 + 一份投影）
```

`code` 吃 level 那份摆过位置的草稿，把它投影成文件。§53 的 `playtestRpg` 吃的也是同一份草稿，
把它用四种固定走法各跑一遍。于是有两种接法：

```
game → combat → level → code → playtest      （A：串成一条）
game → combat → level → { code, playtest }   （B：两格并列，各吃 level 那份）
```

A 看起来"更像一条流水线"，而且作业面板上多一步看起来更完整。但仓库里有一条比"看起来完整"更硬的规矩：
**计划里那条依赖箭头必须有数据可交接**（§113 的 `handoffOf` 就是它的读数）。
`generateGameCode` 从头到尾不读试玩报告——它只吃设计文档。所以 A 里那条 `code → playtest`
的箭头**没有任何东西流过**，它唯一的作用是：试玩跑不出好结果时，把一份本来能拿走的产物一起带走。
那不是流水线，那是把两个互不相干的判断绑成同一次失败。

## 选项

1. **A：串在 code 后面**（`playtest.dependsOn = ['code']`）。否：没有数据流过那条边（背景），
   而且它让"这份设计太难"变成"这份产物拿不走"——两件事在用户那里是两种话。
2. **B：与 code 并列，都只依赖 level**（选定）。两条依赖箭头各有真数据：两边读的都是 level 留在结论里的那份草稿。
3. **C：让 playtest 依赖 combat 而不是 level**（"调完数值就该试"）。否：链末那份**位置也摆好了**的才是
   要交付的那一份，试一份不会进项目的设计等于试了个寂寞（§16：真值是文档，投影要对着同一份真值）。
4. **D：这一格也留一份 `draft`**（"试玩结论"当草稿挂着）。否：与 ADR-0039 同一条理由——
   它没改任何值，留草稿会抢走接受入口的缺省档位（`pickDraft` 取最后一个有草稿的步骤）。

## 决定

1. **`playtest` 成为第九种步骤**，`agentKey: 'qa'`、`requires: 'test.run'`、`artifact: 'playtest_report'`、
   `dependsOn: ['level']`；`code` 的依赖**不动**，仍是 `['level']`。两格在 `readyIds` 里同时就绪
   （声明顺序 playtest 在前，所以就绪清单是 `['playtest', 'code']`）。
   挂 QA 而不是 Game：这一格说的是"通不通、在哪倒下"，名册里那位的能力就是 `test.run`（§73 的能力闸口真的会读它）。
2. **它拿 level 留在结论里的那份草稿，拿不到就整步失败**，话里点名缺的是谁
   （`playtest 这一步没拿到上游草稿（level 那一步没留下 draft）……这一格不另编一份再跑`）。
   守卫失败时 `counts` 是空对象、`notes` 是空数组——"没跑"不许渲染成"0/4 种通关"。
3. **它不产 `draft`、不写库**，界面上因此仍是三颗接受按钮（game / combat / level），缺省那份仍是 level。
4. **报的是 RPG 那条管线**（`playtestRpg(compileRpg(draft))`），与链上前三格、与试玩页同一个分派口径：
   这份草稿在 §51 之后就是 RPG 原型，用底层 `step` 跑它会得出"任务过了"而等级门其实扣着的假报告。
5. **三档读数各自报数，且必须能加回去**：`won` / `lost` / `unfinished`（跑到时间上限）三档，
   `won + lost + unfinished === policies`。只报"几种通关"会把"一直没结束"混进"通不了"里——
   那是 §53 文件头写明的限度，进了链也要在数字上分得开。
6. **限度与 findings 随读数一起进 notes**，一条不少：三条基础限度 + 两条 RPG 限度（跑的是 `rpgStep`、
   升级曲线是投影常量）+ `playtestSeedNote(报告里的种子)`。条数不写死，从 `report.limits.length` 读。
7. **这一格的种子固定用默认值**（不接收入参）：作业里每一步都要逐次可比，换种子是试玩页那一格的事，
   notes 里那句话就写着去哪儿换。相应地 e2e 钉一句：限度里"默认 N"那个数与这一格实际用的种子必须是同一个。

## 后果

- 配方从八步到九步。写死步数的地方一起改，但**该派生的派生**：
  `agent.activity` 条数早已是 `1 + 2 * result.steps.length`，库里结论份数等于计划行数，
  面板那句"N 步作业"读的是 `READINESS_STEPS.length`——这一片加一步，这三处一条都没红，
  红的是真该红的依赖表、终态判定、交接与牵连清单。
- **牵连变宽**：level 失败时 `playtest` 与 `code` **两格**都是 `skipped`（不是 failed），
  通知写"1 步失败，2 步被跳过"，进度分子只有七格而分母是九格，两格各自一条 `agent.step` 都不发。
  这些都在执行层有用例，不是纯层的 `blockedIds` 说了算。
- 反过来（这一条是这一片真正的新增见证）：**playtest 自己失败时 `code` 照跑**，
  `blockedIds` 为空、`readyIds` 仍是 `['code']`、通知只说"1 步失败"。
  纯层为此专门加了一条用例——因为前向的牵连用例**分辨不出谁依赖谁**，
  只有这条反方向的能证明那条 `code → playtest` 的边确实没有被画出来。
- 真浏览器里多了一寸只有浏览器量得到的东西：`counts` 与 `notes` 只在**展开那一格**时才渲染，
  集成测证得了服务端算出了五句限度，证不了那五句画得出来。e2e 因此逐条要求
  `[data-agent-step="playtest"]` 里能读到服务端 notes 的每一句原文，并截一张展开态的图
  （`screenshots/agent-playtest-expanded.png`）。
  **这一片自己就被这条钉了一次**：第一版那句断言抄的是"不穷举"，真话是"不是穷举"，
  于是它红在**测试**身上而不是产品身上——手抄的句子没有对照物就会漂（§159），
  改成从服务端 notes 里派生之后不再有手抄的数。
- 六项读数（`entities` / `policies` / `won` / `lost` / `unfinished` / `maxLevel` / `seed` / `findings` / `limits`）
  进 `counts`，界面上是一行行的 `key value`。e2e 用 `Object.entries(counts)` 逐行要求可见，
  所以以后加一个读数不需要改 e2e，漏渲染才会红。

## 还欠

- §53 的 Capture screenshots / Detect bugs / Fix 三格要浏览器与模型，本机不假生成（§159）。
- 这一格只跑 RPG 那条管线。2D 那五种类型（`playtest` 本体）与对话管线（`playtestStory`）
  在链上还没有各自的一格——真要接的话，得先让链上的草稿带上 kind，而不是像今天这样默认 RPG。
- 试玩报告的读数目前不进 credits 定价，也不参与 `verdictOf`（终态只看有没有 failed/skipped）。
