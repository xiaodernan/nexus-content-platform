# ADR-0148：完成度口径诚实读数——`over` 是「滚过 0% 的 人·天行数」不是人数，`>0` 是刻意语义不动

- 日期：2026-11-12（深夜续）
- 状态：Accepted
- 相关：§168 Analytics、ADR-0123（前端六红线）、`analytics.integration.test.ts`（`>0` 语义的权威钉子）、§A11Y-2 / ADR-0147（同款静态门纪律）
- 编号说明：0146 被 A11Y-1 占、0147 被 A11Y-2 占，本片用 **0148**

## 背景（先量再治，被真测试证伪后方向掉头）

用户长期点名「数据库的性能等的合理运用 / 缓存合理运用 / 前后端协同」，而 analytics 这一层全文件的立身之本是「每个数字说的是不是真话」（`analytics.ts` 文件头：「采不到就报 null，不拿别的数换算一个冒充」）。自主探查时初判 `analytics.ts` 里 `completionPct > 0` 的过滤是「把 0% 访客丢掉」的缺陷，准备把 0% 拉回分母。**读码 + 真测试把初判证伪了**：

```ts
// analytics.integration.test.ts:192 —— 权威的产品语义
// 第三个人一行心跳都没留下（0%），他不该把平均值拉低、也不该被算进 over
await visit(publicationId, { key: KEY(10), completionPct: 0, open: false, visibleMs: 0 });
expect(analytics.completion).toEqual({ avgPct: 60, over: 2 });
```

`>0` 是**刻意语义**：打开即走、一行心跳都没留下的 0% 访客，既不把平均完成度拉低、也不算进 `over`（`rollupVisits` 的 SQL `count(...) filter (where completionPct > 0)`、`totalsOf`/`dailySeries` 的 `filter((row) => row.completionPct > 0)` 三处一致）。若「顺手」改成 `>=0`，就是把一个诚实的产品决定改坏。**方向因此掉头**：算法一个字符不动，真缺陷在别处——口径被文案写反了。

## 真缺陷：数字对、但数字旁的话会被读反

读码坐实 `over` 的真实口径是「滚过 0% 的 **人×天行数**」（`publicationVisits` 一天一人一行，`count` 数的是行），却被三处文案写成会被读成「去重人数 / 全部上报行」的说法：

1. **累计口字段注释**：`AnalyticsNumbers.completion` 写「它是几个访客聚合出来的」；`VisitTotals.completionOver` 写「上面那个平均是几行算出来的」——都没讲 `>0`、没讲 0% 排除、没讲 `over` 是行数不是人数。
2. **UI 显示**：作品表 `CompletionCell` 写 `/ N 人`（同一人分两天各滚过记 2，这里明明是 2 行却说 2 人）、窗口卡写 `N 条上报`（会被读成「每次心跳上报数」）。
3. **口径说明**：`DEFINITIONS` 的「完成度」条点明了「比视口短=100%」，却没点明「打开即走的 0% 不计入」——而这正是 `>0` 语义最该让读者知道的一句。
4. **CSV 导出**：表头 `达标的访客` 同样暗示人数；CSV 是**下载给人看的**表面，代码旁注救不了在 Excel 里打开它的人。

这四处的共同点：算法算的是真话，但数字旁的措辞把读者引向错误理解。本片只治这一层——**口径透明**，不碰聚合算术。

## 做法（零算法变化、零行为变化，仅注释 / 文案 / 表头）

| 表面 | 改前 | 改后 |
|---|---|---|
| `AnalyticsNumbers.completion` 注释 | 「几个访客聚合出来的」 | 明写 `>0` 才进分子与 `over`、0% 不计入、`over` 是「滚过 0% 的 人·天 行数」不是去重人数也不是全部上报行 |
| `VisitTotals.completionPct/completionOver` 注释 | 「有完成度上报的那些行」「几行算出来的」 | 均钉 `>0` + 0% 排除 + 人·天 单位 |
| `DailyPoint.completionPct` 注释 | 「没人上报过完成度时 null」 | 明写只数 `>0`、全 0%（含当天全 0%）是 null 不是 0 |
| CSV `EXPORT_COLUMNS` 表头 | `达标的访客` | `滚过0%的人·天行数` + 列旁完整口径注 |
| 作品表 `CompletionCell` | `/ N 人` | `/ N 人·天` |
| 窗口卡 `data-analytics-window="completion"` | `N 条上报` | `N 个滚过 0% 的 人·天；打开即走的 0% 不计入` |
| `DEFINITIONS` 完成度条 | 未提 0% 排除 | 补「只数滚过 0% 的真人行，打开即走/一秒心跳都没留下的 0% 不计入，`over` 不是去重人数」 |

**为了让纯内存判据能验聚合口径又不建库**：把 `VisitDayRow` / `totalsOf` / `dailySeries` 加 `export`（`getDb()` 本就惰性、`postgres()` 只在调用时建连，只 import 不建连接）。三个导出**只为测试缝**，函数体、调用方、行为一字未动。

**CSV 表头改名的取舍**：这是一处**导出格式变化**（列名文本），会让下游按旧列名取数的脚本受影响——诚实记录这个代价。取舍理由：这一片的名字就是「诚实读数」，而 CSV 表头是唯一一个**下载后脱离本页 DEFINITIONS 单独存在**、却仍直接描述那个数字的表面；留着误导表头、只在代码里加注，等于把这个表面排除在诚实纪律之外。既有 `analytics-export.integration.test.ts` 用 `cell('平均完成度%')` 等标签取数、不依赖旧列名，改名后 33/33 真库集成测全绿，证明仓库内无契约依赖。

## 判据（`apps/web/test/visit-completion-honesty.test.ts`，28 门，零浏览器）

两道门一绿一红，缺一不可；外加判据自身验电：

- **门一 · 纯内存不变量（本就绿，零回归对照，8 门）**：合成 `VisitDayRow[]` 直接喂导出的 `totalsOf`/`dailySeries`，钉死刻意语义——① 0% 不进分母也不拉低（100/20/20/20 + 一个 0 ⇒ 40、over=4，不是 32/5）；② 全 0% 是 `null` 不是 0，但时长/访客照报（`null ≠ 0`）；③ 按行加权不按天平均（40 不是 60）；④ **over 是人·天行数不是去重人数**（同一 key 两天都滚过 ⇒ `over=2` 而 `visitors=1`）——这条正是 UI 改「N 人·天」的可执行证据；⑤ 爬虫 >0 行不进分母只另计 `botOpens`；⑥ `dailySeries` 同口径且日期密集；⑦ 缺的天 `completionPct`/`playTimeMs` 都 null；⑧ 空窗口全 0/null。
- **门二 · 口径措辞（先红，改完转绿，10 门）**：**绑定声明而非「整文件含某词」**，堵住「在别处补一句诚实话就算过」的假绿——`interfaceBody(name)` 按花括号深度取接口体、`jsdocBefore(fieldDecl)` 只认**紧邻**字段的块注释（隔一行代码就返回空）、`lineCommentsBefore(at)` 只收 CSV 列上方连续行注释、`definitionMeaning(label)` 按 label 取那一条的 meaning。`isHonest(text)` 要 **三要素齐**：过滤（`>0`/`滚过 0%`）、排除（`不计入`/`打开即走`…）、单位（`人·天`/`人天`/`人×天`）。含一条**算法保护门**（`>0` 过滤 4 处、`const completed = …>0` 两处一个不少、不许放宽成 `>=0`）与一条**行为门**（直接调 `analyticsCsv([])` 验真实吐出的表头，不只判源码字符串）。
- **门三 · 判据自身验电（9 门）**：同一套谓词喂假片段——旧「几行算出来的」/ 只提 `>0` 不提排除 / 只提排除漏 `>0` / 裸「N 人」/ 隔代码冒充紧邻注释 / 花括号配平 / 行注释连段判断——该红的红、该绿的绿。验电红 = 门没牙，先修门再修生产。

**先红**：精修后 **10 failed | 18 passed（28）**——失败全部落在措辞门（含两条新 CSV 门），门一不变量 8/8 + 门二算法保护 1/1 + 门三验电 9/9 全绿；`analyticsCsv([])` 在无库环境下真实执行不抛，证实纯内存缝成立。**转绿**：改完 8 处表面后 **28/28**。

## 变异臂（六臂，逐条当场备份 + md5 断言变异真发生 + 恢复后 md5 复核）

| 臂 | 变异 | 期望红 | 结果 |
|---|---|---|---|
| A | `>0` → `>=0` | 门一不变量红（钉死刻意语义） | RED `rc=1` |
| B | `completionOver: completed.length` → `humans.length` | 门一不变量红（over 只数 >0） | RED `rc=1` |
| C | CSV 表头改回 `达标的访客` | 门二静态 + 行为红 | RED `rc=1` |
| D | 作品表 `/ N 人·天` 改回 `/ N 人` | 门二红 | RED `rc=1` |
| E | 窗口卡改回 `N 条上报` | 门二红 | RED `rc=1` |
| F | 删 `DEFINITIONS` 的 0% 排除句 | 门二红 | RED `rc=1` |

**事故与诚实记录**：六臂批处理脚本首跑用「文本 grep 提取失败数」判断红绿，臂 A 实际已变红（输出含 `Tests 3 failed`）却被误报成 STAYED GREEN 而 `exit 8`；`trap EXIT` 还原又被并行会话资源抢占的 SIGTERM 打断，臂 C 的 `达标的访客` 变异残留在 `analytics.ts`。**处置**：`grep` 复核发现残留 → 从 mktemp 备份显式恢复两文件 → md5 与绿色基线逐一对齐 → 改用 **vitest 退出码**判红绿（不解析文本）→ 六臂逐条单跑、每条自带 assert + 当场备份 + 恢复后 md5 比对，全部拿到干净的红、文件全部回到基线。**SIGTERM 一律不算绿也不算红**，重跑到有真实退出码为止。

- **横向静态回归（83/83，7 files）**：本片 28 + `forced-colors-style` 9 + `disclosure-controls` 4 + `control-names` 3 + `analytics-agent` + `visit-meter` + `jsx-text`——前两片静态门零回归。
- **工程门**：`eslint` 对 3 个改动文件 0；`tsc -p apps/web --noEmit` 0（`VisitDayRow` 类型导出被判据文件正确消费）。

## 诚实边界（不承诺的事）

- **不声称修了 bug**：算法从始至终正确，`>0` 是刻意语义；本片是**口径透明**，把数字旁会被读反的话改对，不是改数。
- **CSV 列名变化是真实的小破坏**：按 `达标的访客` 取数的外部下游脚本需改列名（仓库内无此依赖，已由 33/33 真库测证明）；这是为「下载后独立存在的表面也说实话」付的代价，明示不藏。
- **措辞门守的是源码字面 + CSV 真实输出**：UI 两处（`N 人·天` / 窗口卡）按源码静态判，未在真浏览器里逐字核对渲染文本；本片纯文本、无交互/计算样式，故未起浏览器，也不伪装起过。
- **真库只跑了 analytics 三套**：其它真库/真 Redis 大套件本片未涉及、未在干净窗口全跑，不编绿灯；墙钟性能实测仍待专门窗口。
- **未 push**，本地领先 `origin/main` 见提交时核对；并行会话的 `application.yml` 等实时编辑文件不在本片 stage 范围。

## 决策

1. 确认 `completionPct > 0` 为刻意产品语义，**保留算法一个字符不动**；任何「把 0% 拉回分母」的改动都必须先推翻 `analytics.integration.test.ts:192` 的权威断言，不得私自放宽。
2. 把 `over` 统一定性为「滚过 0% 的 人·天行数」，在 4 类字段注释、2 处 UI、`DEFINITIONS`、CSV 表头全部说全：`>0` 过滤 + 0% 排除 + 人·天 单位。
3. CSV 表头 `达标的访客` → `滚过0%的人·天行数`，接受列名变化的下游代价，换取下载表面也诚实。
4. 纯函数 `totalsOf`/`dailySeries`/`VisitDayRow` 导出为测试缝（零行为变化），使口径不变量能在无库环境确定性验证。
5. 判据采用「绑定声明的静态门 + 纯内存不变量 + 行为门 + 判据自身验电 + 六变异臂」五件套；红绿只认 vitest 退出码，SIGTERM 不算数。
