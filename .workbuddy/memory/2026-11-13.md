## §CACHE-2 提示词前缀缓存 + 应用缓存命中记账（ADR-0262）

- **起因**：用户第二次报「缓存命中率低、一直显示非流」。上一轮 ADR 0123 / §AILIVE-4 的 95.3%
  全部量自「同一份 payload 连发两次」，证明不了真实多轮。
- **真根因（量出来的）**：`build_prompt` 旧键序把 `selection` / `selectionDigest` / `annotations` /
  `recentChanges` / `corpus` 排在 `pages/frames/components/tokens` 之前。provider 前缀缓存按
  **字节前缀**命中，第一处不同之后全废 —— 真实连续多轮前缀复用率只有 **0.45%**（≈111 B / 24.6 KB）。
  另一处：`_agent_note` 拼在 `system` 里，换 Agent 从第一个字节就失配。
- **修**：载荷三块序（稳定目录 → 每轮现场 → 诉求）；system 只回常量，agent 名册改走载荷
  `agent`/`agentNote`，「没有 design.patch 不许改文档」变成 SYSTEM_PROMPT 第 7 条静态文字；
  稳定块递归剔空（null/""/[]/{}，0/false 不剔）。**0.45% → 96.05%**，system 跨 Agent 恒等，体量 -9.4%。
- **网关数字不可信（关键反证）**：`probe-cache-turns.py` 真机 A/B 新旧序 39.6% vs 39.6%（差 0），
  四实验里 **内容零重叠也报 cached=5248**，同内容两次 `prompt_tokens` 差 500。
  结论：只把可复算的**字节前缀复用率**当对外指标，不用网关 `cached_tokens` 做任何命中率承诺。
- **流式有 usage**：真机 stream=true 拿到 `prompt_tokens=7663 / completion_tokens=36`（34 SSE 帧）。
  `cached_tokens` 的缺席规律后来量清了：**冷前缀不报、暖前缀照报**——
  `stream call1(冷)` 无 `prompt_tokens_details`，`stream call2(暖, 同前缀)` 报 `cached_tokens=7168`
  （7168/7410 = 96.7%）。初稿「流式只缺这一项」过强，已按实测改进 ADR/evidence/ROADMAP/CURRENT-STATE。
  ADR 0123 后的「流式拿不到账本」是误读，流式保留。**仍成立**：没报 ≠ 报了 0。
- **应用级缓存真启用**：`NEXUS_LLM_COMPLETION_CACHE_URL=redis://localhost:56379`（本机 .env，gitignored）
  → `healthz.llmCache backend=redis shared=true`。同 AiRequest 两发：**8689ms → 71.4ms（122×）**，
  `cached=22846=tokensIn`。
- **命中记账修实**（`CachedLlm.complete`）：命中时 `cached_tokens=整段输入`、`latency_ms=查缓存真实耗时`；
  旧行为原样回放当初 Completion，等于把没花的 token、没等的 1.6s 再报一遍。ADR 0113 未定项就此结清。
- **判据**：`test_prompt_order.py` 从「键顺序」改为直接断言连续两轮公共前缀 ≥90%（+system 恒等、
  重建字节相同）；新增 `scripts/prompt-prefix-audit.py`（零成本）与 `scripts/probe-cache-turns.py`（真机）。
  ai-service **296 passed / 11 skipped**。
- **第二片：读数可观测化**（同一天收尾）。`Completion.cache_reported`（默认 False =「没报」不是「报了 0」）
  + `cache_telemetry.py`（`PrefixReuseTracker` 有界 LRU 512 / `ProviderCacheLedger` **分母只算报过账的样本**
  / 零样本给 `null` 不给 `0`）+ `GET /v1/ai/cache-stats`（**不塞 /healthz**，那有 1.5s 探活预算）。
  真机：`prefix.reuseRate=0.5`、`appCache hits=1 misses=1`、`provider.reported=2 missing=0
  reportedHitRate=0.949` —— `missing=0` 就是推翻初稿的那一行。`test_cache_telemetry.py` 9 条，
  ai-service **305 passed / 11 skipped**。
- **仍欠**：**web 契约 `UsageSchema.cachedTokens` 仍是 `default(0)`**（ai-service 已有 `cache_reported`，
