## the reason census finally keys on POSITION, because the word `other` was already spoken for — §11.9b charges a declared reason USED outside its owner (M9 v597 — ADR 0016 amendment 550)

**The hole was disclosed in the present tense, and half of it is now closed.** 549's Bounds said: "A future file could spell the reason face wholesale, or answer `other` with `spam`'s words, and §11 would stay green." The first shape is what §11.9b now charges: a shipped file outside `ops.ts` that uses a declared reason *as a reason* — compares it, switches on it, keys a word table with it, re-declares the list, or wears it as a `data-reason` value — is a red gate. The second shape (a word's VALUE swapped) is still charged by nothing and is carried below as an open bound, not folded into the sentence that closes the first.

**§11.9 could not be copied, and the measurement is why.** The status words are distinctive; spelling one outside its owner is the finding, so 11.9's word-only census is the right shape for them. The reason words are not. Run word-only over the shipped population, **2 files are charged for saying something else entirely**: `apps/studio/src/lib/templateCatalog.ts` keeps `other` in its own six-member category list, and `apps/studio/src/components/DesignSystemPanel.tsx` defaults an unknown path prefix to it. A gate that charges innocent files trains its next reader to ignore it, so the census keys on **position** — where a word is USED as a report reason — and the print line reports both numbers: the chargeable set and the innocent spellings that were looked at and not charged.

**Five positions.** R1 compares a declared reason against an expression that reads `.reason` (or the bare name `reason`). R2 makes one a `case` of a switch whose subject reads `.reason`. R3 finds two or more reason words as the **keys** of one object or type literal — a second word table, which §11.7 cannot see because it counts declarations of the FACE and this declares none. R4 re-declares the **whole** vocabulary as an array or union outside the owner: §11.1 is keyed on the three table NAMES, so `const ALL_REASONS = ['spam','harassment','illegal','other']` walks straight past it. R5 binds a word to a JSX attribute whose name ends in `reason` — the `data-trail-filter="publish"` shape §11.3 already names for verbs.

**Not charged, as a rule.** `{ reason: 'spam' }` is a row WRITTEN with a reason — data the service accepts, not a second speaker — so the keys of a literal matter and its values do not. And `reason` is a polymorphic field name in this client: the ops desk uses it for a route's refusal sentence, whose words can collide with the report vocabulary, so R1 can in principle charge a refusal keyed on a colliding word. Every finding therefore prints `file:rule(word)`; a charged line is meant to be read, not counted.

**Two carriers.** The status census's clean population is guarded by requiring the owner to spell every declared status; 11.9b pins the same for reasons (the owner must spell all **4**), and adds the carrier the word census never needed: the POSITION must be inhabited — **224 `.reason` property reads over 60 shipped files**. "Nobody compares a reason word to `.reason`" is not a contract if no `.reason` exists.
