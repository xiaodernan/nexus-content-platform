### Amendment 550 (v597, m9) — a reason word USED outside its owner is charged at last: §11.9b keys the reason census on POSITION, because the word `other` already belongs to somebody else

- **The hole 549 disclosed, and the half this closes.** 549's Bounds said it in the present tense: "A future file could spell the reason face wholesale, or answer `other` with `spam`'s words, and §11 would stay green." This is the clause for the FIRST shape. A screen may now not test on the wire token and write its own sentence about it: `audit-contract-proof.mjs` §11.9b charges any shipped file outside `ops.ts` that uses a declared reason *as a reason*. The SECOND shape — a word's VALUE changed, `other` answered with `spam`'s sentence — is still open, is still charged by nothing, and is named as open in the Bounds bullet below rather than folded into the sentence that claims it closed.
- **Why §11.9 could not simply be copied.** The five status words are distinctive, so spelling one outside its owner is itself the finding, and 11.9's word-only census is the right shape for them. The four reason words are not: measured at this ref, **2 shipped files spell a declared reason while meaning something else entirely** — `apps/studio/src/lib/templateCatalog.ts` keeps `other` inside its own six-member category list, and `apps/studio/src/components/DesignSystemPanel.tsx` defaults an unknown path prefix to it. Charging those two would make the gate cry wolf, and a gate that cries wolf is a gate the next reader ignores; so the reason census is keyed on **position** — where code USES a reason word as a report reason — and the run prints the innocent spellings beside the chargeable ones so the distinction is visible in the output, not only in this record.
- **The five positions, and the shape each one catches.** R1 compares a declared reason to an expression that reads `.reason` (or to the bare name `reason`). R2 makes one a `case` label of a switch whose subject reads `.reason`. R3 finds two or more reason words as the KEYS of one object or type literal — a second word TABLE, which §11.7 cannot see because that clause counts declarations of the FACE and such a table declares no face. R4 re-declares the WHOLE vocabulary as an array or a union outside the owner, which is the "spell it wholesale" shape 549 named: §11.1 is keyed on the three table NAMES, so `const ALL_REASONS = ['spam','harassment','illegal','other']` walks straight past it. R5 binds a reason word to a JSX attribute whose own name ends in `reason` — the `data-trail-filter="publish"` shape §11.3's comment already names for verbs.
- **What is deliberately NOT charged, said as a rule and not as a gap.** A row WRITTEN with a reason word (`{ reason: 'spam' }`) is data the service accepts, not a second speaker, so R2/R3 do not fire on object literals whose `reason` PROPERTY holds a word — only on literals whose KEYS are words. And the field name `reason` is polymorphic in this client: the ops desk uses it for a route's refusal sentence, which can carry a word that collides with the report vocabulary. R1 therefore *can* in principle charge a refusal keyed on a colliding word. That is why every finding prints `file:rule(word)` — a charged line is meant to be read, not only counted.
- **Two carriers, because an absence claim needs a witness.** 11.9's clean status census is guarded by a clause that requires the owner to spell every declared status, so a `spellings()` that parsed nothing could not report a clean population; 11.9b carries the same pin for reasons (the owner must spell all **4** declared reasons as string literals) AND a second one the status clause does not need: the POSITION the rules key on must be inhabited, measured here as **224 `.reason` property reads over 60 shipped files**. "Nobody compares a reason word to `.reason`" is a contract only if a `.reason` exists to compare against.
