## 经验（可复用）

1. **"恒为假/恒为真"的守卫是一类会静默放行的 bug**，而且**typecheck 与 eslint 都抓不到**：
   实测 `@typescript-eslint/no-unnecessary-condition` **不跨合取式推理**，
   对 `a && b && !a` 不报。本仓库当前规则集也不报。
   → 这类写法唯一的防线是**测那道守卫本来想守的行为**（不是测"函数返回了"）。
   同族的上一例是 `if (false) { await recordAudit(...) }`（那次 eslint 的 no-constant-condition 抓到了）。
2. **接手未提交切片的标准动作**（第二次用到，已成熟）：
   `git status` → 看 `MM`（已暂存又有新改动）说明是半途状态 → 跑 lint + 相关测试确认起点
   → 判断红的是"没写完"还是"写错了" → 修根因 → 补测 + 变异探针 → 全量验证 → 提交。
3. **变异探针要写在提交信息里**（本项目已把它当凭证）：不只说"测试通过"，
   要说"把某行改回旧写法 → 红在哪句话上 → 改回后几条全过"。
4. eslint 的 `no-base-to-string` 很有用：测试里 `String(unknownValue ?? '')` 会把对象变成
   `"[object Object]"`，制造"看起来有值"的假绿。用类型收窄替代 `String()`。

## 经验（这一轮新长的）

1. **"吸附"这类看着像审美的处理，可能是写库能不能成功的前提。** 去掉吸附的探针没有红在"数字不整"，
   而是红在"**库里根本没变**"——契约里 `durationMs` 是 `z.number().int()`，非整数毫秒整份 PUT 被拒。
   探针给出的理由比我原本写的那个更硬：先探针，再写结论。
2. **截图要复看，而且要在"东西真的在视口里"的时候拍。** 第一版序号与时长是居中流排版，转场标记盖住了
   "4.5s" 的 4；拖整块时那一格被条的 `overflow-hidden` 裁到看不见——两处都是看截图才发现的。
   另外点面板顶部那排按钮（撤销）会把面板滚回头部，所以**截图前先 `scrollIntoViewIfNeeded`**，
   否则拍到的是一屏没有新东西的画面（第一张就是这样拍空的）。
3. **264px 的面板里做"编辑器"要按像素定阈值**：一格 47px 放不下"转场标记 + 序号 + 时长"三段居中文字，
   所以三处全用绝对定位（左上 / 右上 / 底部居中），并按量出来的条宽决定哪一段显示。
4. **`elementFromPoint` 返回 null 是"目标在视口外"的信号**：Playwright 的 `boundingBox()` 照样给坐标，
   鼠标事件却落不到那个点上。这一条把"拖拽不动"从"事件没绑上"里分了出来（省了一次瞎改）。
5. **同一个 checkout 上跑两个会话时，门禁是共用的**：pre-commit 钩子跑整棵树的 `npm run lint`，
   另一条线留着语法半成品时自己就提交不了（实测被挡一次：`analytics.ts` 的 `DAY_MS` 未使用，
   那是对方正在改的文件，几十秒后它自己就干净了）。纪律：动手前 `git status`、提交只 `git add` 自己的路径、
   **不绕钩子**，被挡就等对方那一段落地再重试。
