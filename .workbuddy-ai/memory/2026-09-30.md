## 经验（可复用，本轮最值钱的部分）

1. **"文档/代码互相说谎"是本项目最高频的缺陷类别**，本轮抓到三类：
   - **恒为假的守卫**（上轮 `a && b && !a`；更早 `if (false)`）——typecheck 与 eslint 都抓不到
     （实测 `no-unnecessary-condition` 不跨合取式推理）。
   - **错引一份存在的文档**（`plan-admin.ts` 说"写在 ADR-0019 里"，而 0019 讲的是 API 凭据）。
     错引比不写更难查。
   - **过期的事实陈述**（ROADMAP/ARCHITECTURE 说"build.status 还没有生产者"，
     而代码里已经有；说"改档位没有界面"，而界面已经写好）。
   **动作**：接手任何切片前，把"代码 / 注释 / 文档"三处说法摆在一起读；写完代码顺手 grep 一遍
   那句被推翻的话，改掉它（用 `~~删除线~~` + 日期更新，保留历史）。
2. **变异探针要写进 commit message**（本项目已把它当凭证）：不只说"测试通过"，
   要说"改回旧写法 → 红在哪句话上 → 改回后几条全过"。
3. **结构门（扫源码的测试）是本项目对付"靠人眼抓不住"的武器**。已成型的两道：
   `api-response.test.ts`（v1 不许裸 `NextResponse.json`）、`jsx-text.test.ts`（JSX 不许漏 markdown 粗体）。
   写这类测试的要点：**先断言"扫到的文件数不为零"**，否则空集也能绿成"干净"。
4. **脚本也要进 typecheck**：`scripts/diag-selection.mts` 用 `tsx` 跑，`tsx` 不做类型检查，
   于是一处 `unknown` 参与算术的错一直没暴露，直到 `npm run lint` 把它挡下。
5. **接手别的会话的在途工作时**：读 ROADMAP 末尾的"交接点"，那里常写着
   "只 git add 自己改过的路径"这类并发约定。用 `git commit -- <paths>` 做部分提交，
   别把别人半成品一起提交进去。
