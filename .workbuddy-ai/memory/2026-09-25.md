## 经验（可复用）

1. **ESLint 规则集的价值第一次兑现**：`no-constant-condition` 直接指出一处被 `if (false)` 关掉的
   业务调用，而 typecheck / 单测 / 集成测试全都没抓到它（测试是红的但没人跑）。
   lint 现在是 `typecheck && eslint` 两段。
2. **接手未提交工作的标准动作**：先 `git status` 看有什么 → 跑 lint + 相关测试确认起点
   → 红的地方先判断"是没写完还是写错了"（本轮是没写完：测试写了、实现被关掉）
   → 修根因 → 全量验证 → 才提交。
3. **交叉核对文档/注释/UI 三处说法**：本轮第 2 处问题是注释与 UI 文案互相矛盾，
   只读代码看不出来，必须把三处摆在一起读。
4. 新写入路径要顺手问一句"谁能触发它、有没有限流"——审计写入是新的放大面。
