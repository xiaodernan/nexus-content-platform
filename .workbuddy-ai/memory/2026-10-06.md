## 审计：注销账号（4604b5b）——没找到 bug，记下查过什么

这是最近落地里唯一动别人数据的一格，所以逐条查了：
- `personRow()` **不过滤** `deletedAt` → 所以 `if (person.deletedAt) return already_deleted`
  那道守卫是**活的**，不是死代码（这是本项目最高频的缺陷类别，每次都要先查）。
- 预览与执行**共用** `unpublishedLiveProjects()` 那一句 → 界面上"会收起 3 个"与实际不会分叉。
- 并发保护是 CAS：用户行 `update ... where isNull(deletedAt)`，后到的那次拿到 0 行抛错整个回滚，
  不留"会话没了人还在"的半截。
- 路由：CSRF → JSON → zod → 鉴权 → 限流（5 次 / 10 分钟）→ 提交后摘 cookie，顺序对。
- `requireUser()` 是**抛错**而不是造 guest（guest 由 middleware 签发），所以"匿名请求会造一行库"不成立。

## 经验

1. **`git commit -- <paths>` 会把已暂存的其它文件一起带上**。我按 pathspec 提交游戏那一片时，
   三个已暂存的健康面板文件被一起提交了，而我的信息里没写它们。
   **动作**：提交前先 `git diff --cached --stat` 看清索引里有什么；
   发现信息与内容不符时，**`--amend -m` 把信息补全**（本地未推送、自己几分钟前的提交，
   改信息不丢任何东西），比留着一条描述不全的记录好。
2. **lint 的 ENOENT 可能只是竞态**，重跑一次再判断，别急着改配置。
3. **判断有没有活跃会话**：`stat -c '%y'` 看未提交文件的 mtime + 当前时间。
   两分钟前刚改过 → 有人在写，别动他的文件、别用 `--no-verify` 绕他的半成品。
4. **普查类测试必须带 reach**：`notify-producers.test.ts` 的第一版只查"文件里出现过 `kind:'like'`"，
   于是把只写互动表、从不 `emit` 的 `social.ts` 也算成生产者，得到一张"十类都有生产者"的**假名单**。
   判据要落到"这条通知真发得出去"，而不是"这个字符串出现过"。
