## §49 语料索引与混合检索：收尾 + 修掉一个 100% 失败的 bug

**状态检查**：M0/M1/M2 已全部 commit，M3 进行中（World Builder / World Graph / Character §46 /
Memory §48 均已落地）。本轮接手时工作区有未提交的 §49 切片（~911 行）。

**修掉的真 bug（重要）**：`knowledge.ts` 检索条件把词条拼成一个字符串塞进 drizzle 的
`sql` 模板，drizzle 当**单个绑定参数**处理，生成 `or $6`（$6 是文本），
Postgres 报 `argument of OR must be type boolean, not type text`
→ **任何非空查询都失败**，检索面板整个不可用。

- 单测抓不到（纯函数那半不碰 SQL），集成测试能抓但需要真库
- **发现手法值得复用**：不连库，用 drizzle 的 `.toSQL()` 把渲染结果打出来看
  （建一个惰性 postgres 客户端即可，不会真连接）
- 修法：逐条生成条件再 `or(...)`，每个词条各自成为绑定参数
- 防复发：条件构造抽成纯函数 `buildRetrievalFilter(projectId, query)`，
  补 4 条不连库的 SQL 断言

**顺带修**：`addMemory` 对「我的偏好」类记忆（project_id = null，不在任何语料库）
也触发全量重建，白做一次全量删写 → 改成与 `deleteMemory` 同一判断。

**验证**：`npm run lint` 通过；`knowledge.test.ts` 11/11；非库测试 26 files / 317 tests 全绿。
commit `19f8050`。
